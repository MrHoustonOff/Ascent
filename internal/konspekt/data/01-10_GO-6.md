## GO-6. Указатели

### GO-6.1 Указатель в Go

#### GO-6.1.1 Указатель
**Вопросы**
- [ ] Что такое указатель? · `go pointer explained simply`
- [ ] Чем значение указателя отличается от значения переменной, на которую он указывает? · `pointer value vs pointed value`
- [ ] Сколько байтов занимает указатель на 64-битной системе и зависит ли это от того, на что он указывает? · `pointer size 64 bit 8 bytes`
- [ ] Почему в Python указателей «не видно», хотя имена там по сути и есть ссылки на объекты? · `python references vs go pointers`
- [ ] Чем указатели в Go безопаснее, чем в C? · `go pointers safer than c`

**Гуглить:** `golang pointers tutorial` · `go tour pointers` · `what is a pointer`

**Должен знать**
Указатель — переменная, в которой лежит адрес другой переменной. Сам указатель — обычное значение размером в 8 байт (на 64-битной системе), сколько бы ни занимало то, на что он указывает. Через указатель можно прочитать и изменить ту переменную, на которую он указывает.
В Python каждое имя — это скрытая ссылка, и управлять ею явно нельзя. В Go ты сам решаешь, передать значение или адрес. При этом Go не даёт вычислять адреса произвольно, а за памятью следит сборщик мусора — поэтому указатели здесь гораздо безопаснее, чем в C.

**Термины**
- **указатель** *(новое)* — переменная, хранящая адрес другой переменной

#### GO-6.1.2 Оператор & и тип *T
**Вопросы**
- [ ] Что делает `&x` и что означает тип `*int`? · `go & operator *int type`
- [ ] Какой тип у `&x`, если `x` — `string`? · `go address of string type`
- [ ] Можно ли взять адрес у `&5` или у результата функции `&f()`? · `go cannot take address of`
- [ ] Можно ли присвоить `*int` переменной типа `*int64`? · `go pointer types not interchangeable`
- [ ] Как напечатать указатель (`%p`) и что ты увидишь? · `go print pointer %p`

**Гуглить:** `golang address operator` · `go pointer type syntax`

**Должен знать**
`&x` — взятие адреса: результат имеет тип `*T`, где `T` — тип `x`. Так `p := &x` при `x int` даёт `p` типа `*int` — «указатель на `int`». Тип указателя строгий: `*int` и `*int64` несовместимы.
Адрес можно взять только у того, что где-то хранится, — у переменной; у числа в коде или у результата вызова функции адреса нет.

**Термины**
- **`&`** — получить адрес переменной
- **`*T`** — тип «указатель на значение типа `T`»

**Граница:** `&` у составных значений вроде `&T{…}` — позже, в GO-10.1.3.

#### GO-6.1.3 Разыменование
**Вопросы**
- [ ] Что делает `*p` в выражении? · `go dereference pointer`
- [ ] Чем `*` в типе `*int` отличается от `*` в выражении `*p`? · `go asterisk type vs dereference`
- [ ] Что выведет `x := 1; p := &x; *p = 5; fmt.Println(x)`? · `go change value through pointer`
- [ ] Что произойдёт после `q := p`: сколько теперь указателей на `x` и что будет при `*q = 7`? · `copy pointer same address`
- [ ] Чем `p = &y` отличается от `*p = y`? · `assign pointer vs assign through pointer`

**Гуглить:** `golang dereferencing` · `go pointers & and *`

**Должен знать**
Разыменование `*p` — доступ к переменной, на которую указывает `p`: прочитать `v := *p` или изменить `*p = 5`. Значок `*` в типе (`*int`) и в выражении (`*p`) означает разное: в типе — «указатель на», в выражении — «то, на что указывает».
Копия указателя указывает туда же: после `q := p` изменения через `*q` видны через `*p` и в самой `x`. `p = &y` перенаправляет указатель, а `*p = y` меняет значение там, куда он указывает.

**Термины**
- **разыменование** *(новое)* — `*p`: доступ к значению по адресу из указателя

#### GO-6.1.4 nil-указатель
**Вопросы**
- [ ] Какое нулевое значение у указателя? · `go pointer zero value nil`
- [ ] Что будет при разыменовании nil? · `nil pointer dereference panic`
- [ ] Как выглядит сообщение `invalid memory address or nil pointer dereference` и как найти причину? · `go invalid memory address or nil pointer dereference`
- [ ] Как защититься проверкой `if p != nil`? · `go check pointer nil`
- [ ] Чем nil в Go похож на `None` в Python и чем отличается? · `go nil vs python none`

**Гуглить:** `golang nil pointer` · `nil pointer dereference go`

**Должен знать**
Указатель, которому не присвоили адрес, равен nil — «ни на что не указывает». Разыменование nil вызывает панику `invalid memory address or nil pointer dereference`. Это одна из самых частых паник в Go.
Если указатель может быть nil, проверяй его перед использованием: `if p != nil { … }`, и с ленивым вычислением `p != nil && *p > 0`. В отличие от `None`, nil — не отдельный объект, а нулевое значение для указателей и ещё нескольких видов типов.

**Термины**
- **nil** *(новое)* — нулевое значение указателя: «нет адреса»

#### GO-6.1.5 Почему в Go нет арифметики указателей
**Вопросы**
- [ ] Почему в Go нельзя прибавить к указателю число? · `go no pointer arithmetic why`
- [ ] Что такое арифметика указателей в C и какие ошибки она порождает? · `pointer arithmetic c buffer overflow`
- [ ] Как отсутствие арифметики помогает сборщику мусора? · `pointer arithmetic garbage collector`
- [ ] Что такое пакет `unsafe` и почему его обходят стороной? · `go unsafe package`

**Гуглить:** `go faq pointer arithmetic` · `golang unsafe pointer`

**Должен знать**
В C можно прибавить к указателю число и попасть в соседнюю память — так легко выйти за пределы своих данных и испортить чужие. В Go это запрещено: указатель всегда ведёт ровно на ту переменную, адрес которой взяли. Благодаря этому сборщик мусора точно знает, какие данные ещё используются.
Обойти запрет можно пакетом `unsafe`, но, как видно из имени, в обычном коде им не пользуются.

**Термины**
- **арифметика указателей** — вычисление адресов сложением с указателем; в Go запрещена

**Граница:** пакет unsafe — одной фразой.

### GO-6.2 Зачем указатели

#### GO-6.2.1 Изменение чужой переменной через указатель
**Вопросы**
- [ ] Как функции изменить переменную вызывающего? · `go modify variable in function pointer`
- [ ] Перепиши `double(x int)` из GO-4.2.2 так, чтобы она меняла переменную вызывающего. · `go pointer parameter example`
- [ ] Если в функцию передали указатель, что именно копируется? · `go passing pointer copies address`
- [ ] Когда передавать в функцию указатель, а когда значение? · `go pointer vs value parameter`
- [ ] Почему указатель на `int` ради «экономии» — плохая идея? · `go pointer to small value performance`

**Гуглить:** `golang pass pointer to function` · `go when to use pointers`

**Должен знать**
Аргументы всегда копируются, но если скопировать адрес, обе копии указывают на одну переменную. Поэтому `func double(p *int) { *p *= 2 }` и вызов `double(&x)` меняют `x` у вызывающего.
Указатель передают, когда функция должна изменить значение или когда значение очень большое и копировать его дорого. Для маленьких значений вроде `int` указатель ничего не экономит, зато добавляет риск nil и усложняет чтение.

**Термины**
- **параметр-указатель** — параметр с типом `*T`, через который функция меняет чужую переменную

#### GO-6.2.2 Функция new
**Вопросы**
- [ ] Что делает `new(int)` и что лежит по полученному адресу? · `golang new function`
- [ ] Чем `new(int)` отличается от `var x int; p := &x`? · `go new vs address of variable`
- [ ] Почему `new` в Go используют редко? · `go new rarely used`
- [ ] Что добавилось в Go 1.26: `new(выражение)`? · `go 1.26 new expression`

**Гуглить:** `go new builtin` · `go new vs &`

**Должен знать**
`new(T)` создаёт переменную типа `T` с нулевым значением и возвращает указатель на неё. Это то же самое, что объявить переменную и взять её адрес, только без имени. На практике чаще пишут `&x` или `&T{…}`, поэтому `new` встречается нечасто.
С Go 1.26 `new` принимает и выражение: `new(42)` — указатель на новую переменную со значением 42.

**Термины**
- **`new`** — функция языка: создать переменную с нулевым значением и вернуть её адрес

**Граница:** new(выражение) с Go 1.26 — одной строкой.

#### GO-6.2.3 Указатель на локальную переменную
**Вопросы**
- [ ] Можно ли вернуть из функции указатель на её локальную переменную? · `go return pointer to local variable`
- [ ] Почему в C это ошибка: что станет с кадром после возврата? · `c return address of local variable dangling pointer`
- [ ] Почему в Go это безопасно и кто об этом заботится? · `go escape analysis local variable heap`
- [ ] Чем за эту безопасность приходится платить? · `heap allocation cost go`

**Гуглить:** `go return pointer local variable safe` · `dangling pointer c`

**Должен знать**
В C локальная переменная живёт в кадре стека, кадр исчезает при возврате, и указатель на неё становится «висячим» — ведёт в память, которую скоро займут другие данные. В Go такой код корректен: компилятор видит, что адрес переменной уходит за пределы функции, и кладёт её не в кадр, а в кучу. Освободит её сборщик мусора, когда указателей не останется.
Цена — выделение в куче и работа сборщика, поэтому указатели «просто так» не возвращают.

**Термины**
- **висячий указатель** — указатель на память, которая уже освобождена (в C)

**Позже:** как Go это обеспечивает — GO-21.1.2.

#### GO-6.2.4 Ввод с клавиатуры: fmt.Scan
**Вопросы**
- [ ] Как прочитать число с клавиатуры через `fmt.Scan`? · `golang fmt.Scan example`
- [ ] Почему `fmt.Scan` принимает указатели? · `why fmt.Scan needs pointer`
- [ ] Что вернёт `fmt.Scan` и как понять, что ввод неверный? · `fmt.Scan return values error`
- [ ] Чем `fmt.Scan` отличается от `fmt.Scanln` и как прочитать целую строку с пробелами? · `go read line from stdin bufio`
- [ ] Чем это отличается от `input()` в Python? · `python input vs go scan`

**Гуглить:** `golang read input from console` · `fmt.Scan pointer` · `bufio.Scanner stdin`

**Должен знать**
`var n int; fmt.Scan(&n)` читает значение из ввода и кладёт его в `n`. Указатель нужен потому, что аргументы копируются: только через адрес функция может записать результат в твою переменную. `fmt.Scan` возвращает, сколько значений удалось прочитать, и признак ошибки — их стоит проверять.
`fmt.Scan` делит ввод по пробелам; чтобы прочитать целую строку, используют `bufio.Scanner`. В Python `input()` возвращает строку, которую потом приходится разбирать; в Go разбор встроен в чтение.

**Термины**
- **`fmt.Scan`** — чтение значений из ввода в переменные по их адресам

**Граница:** `bufio` подробно — не нужно.

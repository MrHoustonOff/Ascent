- [ ] Что такое пакет в Go и как он связан с папкой? · `go package what is`
- [ ] Почему каждый файл `.go` начинается со строки `package имя`? · `go package declaration`
- [ ] Чем особенный пакет `main` и почему исполняемая программа должна быть в нём? · `go package main meaning`

**Гуглить:** `how to write go code packages` · `пакеты в go простыми словами`

**Должен знать**
Пакет — папка с файлами `.go`, у которых одинаковая первая строка `package имя`. Модуль состоит из пакетов.
Пакет `main` особый: только из него собирается исполняемый файл. Все остальные пакеты — библиотеки: их код используют другие пакеты, а сами по себе они не запускаются. В одной папке может быть только один пакет.

**Термины**
- **пакет** *(новое)* — папка с файлами `.go` с одной строкой `package`
- **`package main`** — пакет, из которого собирается исполняемый файл
- **библиотечный пакет** — пакет, который не запускается сам, а используется другими

**Граница:** исключение для тестовых файлов (`_test`) — не нужно.

#### GO-1.2.3 func main и точка входа
**Вопросы**
- [ ] С какой функции начинается выполнение программы на Go? · `go func main entry point`
- [ ] Почему у `main` нет параметров и результата? Как тогда получить аргументы командной строки и вернуть код выхода? · `go os.Args os.Exit`
- [ ] Что будет, если в пакете `main` нет функции `main`? · `function main is undeclared in the main package`
- [ ] Что происходит с программой, когда функция `main` заканчивается? · `go program exits when main returns`
- [ ] Чем это отличается от Python, где файл выполняется сверху вниз, а `if __name__ == "__main__"` — лишь договорённость? · `python __name__ main vs go main`
- [ ] Выполняется ли что-нибудь до `main`? · `go what runs before main`

**Гуглить:** `go main function` · `точка входа программы go`

**Должен знать**
Точка входа — место, откуда начинается выполнение. В Go это `func main()` в пакете `main`: без параметров и без результата. Аргументы командной строки лежат в `os.Args`, а код выхода задаётся через `os.Exit`. Когда `main` возвращается, вся программа завершается.
В Python выполняется весь файл подряд, а `__name__ == "__main__"` — только идиома. В Go нет кода «на верхнем уровне файла»: всё выполняемое живёт внутри функций.

**Термины**
- **точка входа** *(новое)* — функция, с которой начинается выполнение программы
- **`os.Args`** — аргументы командной строки
- **код выхода** — число, которое программа возвращает ОС при завершении (0 — успех)

**Позже:** функция `init`, которая выполняется до `main` — GO-5.2.2; что происходит с параллельными задачами, когда `main` завершается — GO-15.1.3.

#### GO-1.2.4 Вывод на экран: fmt.Println, fmt.Printf и глаголы форматирования
**Вопросы**
- [ ] Чем отличаются `fmt.Print`, `fmt.Println` и `fmt.Printf`? · `go fmt print println printf difference`
- [ ] Что такое глагол форматирования? · `go printf verbs`
- [ ] Что выводят `%d`, `%s`, `%v`, `%f`, `%t`, `%q`, `%T`? · `go fmt verbs cheat sheet`
- [ ] Как вывести дробное число с двумя знаками после запятой и выровнять число по ширине? · `go printf %.2f width`
- [ ] Почему `Printf` не переходит на новую строку и как это исправить? · `go printf newline`
- [ ] Что возвращает `fmt.Sprintf` и где это полезно? · `go sprintf example`
- [ ] Что выведет `Printf` с неподходящим глаголом, например `%d` для строки? · `go printf %!d(string=`
- [ ] Что в Python делает то же, что `Printf` (f-строки, `%`, `format`)? · `python f-string vs go printf`

**Гуглить:** `pkg.go.dev fmt` · `fmt printf глаголы go`

**Должен знать**
`Println` печатает значения через пробел и переводит строку, `Print` — без перевода строки, `Printf` — по шаблону. В шаблоне глаголы форматирования показывают, как вывести значение: `%d` — целое, `%s` — строка, `%v` — «как есть» для любого значения, `%T` — тип, `%q` — строка в кавычках, `%.2f` — дробное с двумя знаками.
`Printf` не добавляет перевод строки — нужен `\n`. `Sprintf` делает то же, но возвращает строку вместо вывода. Неподходящий глагол не ломает сборку, а печатает предупреждение прямо в выводе.

**Термины**
- **глагол форматирования** *(новое)* — `%`-код в шаблоне `Printf`, который задаёт вид значения
- **`%v`** — универсальный глагол «вывести как есть»
- **`Sprintf`** — форматирование в строку без вывода

**Граница:** все флаги и тонкости — в документации пакета `fmt`; наизусть достаточно основных глаголов.

#### GO-1.3.2 Команда go build
**Вопросы**
- [ ] Что делает `go build` и где появляется исполняемый файл? · `go build output file`
- [ ] Как задать имя готового файла? · `go build -o`

**Должен знать**
`go build` компилирует пакет и кладёт исполняемый файл рядом (имя по умолчанию — от папки модуля); флаг `-o` задаёт имя и путь. Все нужные части сразу попадают внутрь файла, поэтому его можно отдать пользователю: ни Go, ни других файлов ему не нужно — только та же ОС и тот же тип процессора.

**Термины**
- **`go build`** — собрать исполняемый файл
- **статическая сборка** — всё нужное для работы лежит внутри одного исполняемого файла

#### GO-1.3.3 Рантайм Go
**Вопросы**
- [ ] Что такое рантайм Go? · `go runtime what is`
- [ ] Где находится рантайм: отдельная программа, как CPython, или часть исполняемого файла? · `go runtime embedded in binary`
- [ ] Какую работу рантайм делает за программу (в общих словах)? · `go runtime responsibilities`
- [ ] Почему наличие рантайма не делает Go интерпретируемым языком? · `go runtime vs interpreter`
- [ ] Что в Python играет похожую роль и чем это отличается? · `cpython runtime memory management`
- [ ] Почему именно рантайм — главная причина размера исполняемого файла hello world? · `go runtime binary size`

**Гуглить:** `go runtime package` · `рантайм go что это`

**Должен знать**
Рантайм — вспомогательный код Go, который компилятор добавляет в каждый исполняемый файл. Он работает внутри процесса рядом с твоим кодом: выделяет и автоматически освобождает память, распределяет работу по ядрам процессора, следит за ошибками во время работы.
Это не интерпретатор: твой код уже переведён в машинные инструкции, рантайм лишь помогает ему. В Python похожую роль играет сам CPython — он и выполняет байткод, и управляет памятью, поэтому его приходится ставить отдельно. Рантайм Go едет внутри файла — поэтому файл и весит больше, чем ждёшь.

**Термины**
- **рантайм** *(новое)* — вспомогательный код Go внутри каждого исполняемого файла

#### GO-1.3.4 Кросс-компиляция: GOOS и GOARCH
**Вопросы**
- [ ] Что такое кросс-компиляция? · `cross compilation what is`
- [ ] Что задают настройки `GOOS` и `GOARCH`? Какие у них частые значения? · `go GOOS GOARCH values`
- [ ] Как на Windows собрать файл для Linux на amd64: как задать `GOOS`/`GOARCH` прямо перед `go build` в терминале? · `go cross compile windows to linux`
- [ ] Как посмотреть все поддерживаемые пары ОС и процессора? · `go tool dist list`
- [ ] Почему в Go кросс-компиляция работает «из коробки», а с `CGO_ENABLED=1` усложняется? · `go cross compile cgo`
- [ ] Как ты собирал PhoneGyro под `windows/arm64` и зачем отдельная сборка для Windows на ARM? · `go build windows arm64`

**Гуглить:** `go cross compile guide` · `кросс-компиляция go goos goarch`

**Должен знать**
Кросс-компиляция — сборка исполняемого файла для другой ОС или другого процессора, не выходя со своей машины. В Go для этого достаточно задать `GOOS` (linux, windows, darwin) и `GOARCH` (amd64, arm64) и выполнить `go build`.
Это работает потому, что Go сам умеет генерировать машинные инструкции для всех поддерживаемых наборов инструкций. Если в проекте есть код на C (`cgo`), нужен ещё и компилятор C под целевую платформу — это усложняет дело.

**Термины**
- **кросс-компиляция** *(новое)* — сборка под другую ОС или другой процессор
- **`GOOS` / `GOARCH`** — целевая ОС и целевой процессор сборки
- **`CGO_ENABLED`** — разрешает или запрещает код на C в сборке

#### GO-1.4.3 Точки с запятой и положение фигурной скобки
**Вопросы**
- [ ] Почему в коде на Go почти нет точек с запятой, хотя язык их использует? · `go automatic semicolon insertion`
- [ ] По какому правилу компилятор сам ставит точку с запятой в конце строки? · `go semicolon insertion rule`
- [ ] Почему из-за этого правила открывающую `{` нельзя перенести на новую строку после `func main()` или `if`? · `go opening brace new line error`
- [ ] Какую ошибку покажет компилятор в этом случае? · `unexpected semicolon or newline before {`
- [ ] Где точки с запятой всё-таки пишут явно? · `go for loop semicolons`
- [ ] Почему единый стиль скобок полезен команде? · `go one true brace style`

**Гуглить:** `go spec semicolons` · `точка с запятой go`

**Должен знать**
Грамматика Go требует точку с запятой в конце инструкций, но компилятор ставит её сам: если строка заканчивается именем, числом, строкой, `)`, `]`, `}` или ключевым словом вроде `return`. Поэтому `{` всегда пишут на той же строке: иначе после `func main()` встанет точка с запятой, и сборка упадёт.
Явно точки с запятой пишут, например, в заголовке цикла `for i := 0; i < n; i++`. Жёсткое правило снимает споры о стиле.

**Термины**
- **автоматическая вставка `;`** — компилятор сам завершает строку по простому правилу

#### GO-1.4.4 gofmt и go vet
**Вопросы**
- [ ] Что делает gofmt и почему в Go нет споров о стиле кода? · `gofmt why`
- [ ] Чем `gofmt` отличается от `go fmt`? · `gofmt vs go fmt`
- [ ] Что делает goimports? · `goimports vs gofmt`
- [ ] Что ищет go vet и чем он отличается от компилятора? · `go vet what does it check`
- [ ] Какие ошибки ловит go vet: неверный глагол в `Printf`, код, который никогда не выполнится, и другие? · `go vet printf check example`
- [ ] Почему `go test` сам запускает часть проверок go vet? · `go test runs vet`
- [ ] Как включить форматирование при сохранении в редакторе? · `vscode go format on save`

**Гуглить:** `go vet analyzers list` · `gofmt и go vet разница`

**Должен знать**
gofmt приводит код к единственному официальному стилю: отступы, пробелы, переносы. Спорить о стиле в Go не о чем — все форматируют одинаково, обычно автоматически при сохранении. `go fmt` — команда, которая запускает gofmt для пакетов, а goimports ещё и расставляет импорты.
go vet ищет подозрительные места, которые компилятор пропускает: неверные глаголы в `Printf`, код, который никогда не выполнится, бессмысленные сравнения. Код, который проходит go vet, не обязательно верный, но очевидных ловушек в нём меньше.

**Термины**
- **gofmt** *(новое)* — автоматический форматировщик кода
- **go vet** *(новое)* — проверка подозрительных конструкций сверх компилятора
- **goimports** — gofmt плюс автоматическая расстановка импортов

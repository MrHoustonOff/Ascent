## GO-10. Структуры

### GO-10.1 Структура

#### GO-10.1.1 Структура
**Вопросы**
- [ ] Как объявить структуру `type User struct { Name string; Age int }`? · `golang struct declaration`
- [ ] Как обратиться к полю и изменить его? · `go struct field access`
- [ ] Чем структура в Go похожа на `dataclass` в Python и чем отличается от класса (нет иерархии классов, нет `self`)? · `go struct vs python class dataclass`
- [ ] Почему поля, как и другие имена, экспортируются заглавной буквой? · `go exported struct fields`
- [ ] Почему структуру называют «значением», как массив? · `go struct value type`

**Гуглить:** `go tour structs` · `golang structs explained` · `python dataclass`

**Должен знать**
Структура — тип из набора именованных полей разных типов: `type User struct { Name string; Age int }`. Поле читают и меняют через точку: `u.Name = "Аня"`. Поля с заглавной буквы видны из других пакетов, со строчной — только в своём.
Мост из Python: похоже на `dataclass` — данные с именами полей. Но это не класс: нет иерархии классов, нет `__init__`, а поведение добавляется отдельно. И главное — структура — значение, как массив: копируется целиком.

**Термины**
- **структура** *(новое)* — тип из именованных полей: `struct { … }`
- **поле** — именованная часть структуры

**Позже:** поведение для своих типов — GO-11.1.1.

#### GO-10.1.2 Литерал структуры и нулевое значение
**Вопросы**
- [ ] Как создать значение структуры литералом с именами полей и без них? · `go struct literal named fields`
- [ ] Почему литерал без имён полей (`User{"Аня", 30}`) — плохая практика? · `go struct literal unkeyed fields vet`
- [ ] Какое нулевое значение у структуры? · `go struct zero value`
- [ ] Можно ли указать в литерале только часть полей? · `go struct literal omit fields`

**Гуглить:** `golang struct literal` · `go vet composites`

**Должен знать**
`u := User{Name: "Аня", Age: 30}` — литерал с именами полей; пропущенные поля получают нулевые значения. Литерал без имён `User{"Аня", 30}` требует все поля по порядку и ломается при добавлении нового поля — для чужих типов `go vet` об этом предупреждает.
Нулевое значение структуры — все поля с нулевыми значениями. `var u User` — уже готовая к работе структура.

**Термины**
- **литерал структуры** — `T{Поле: значение, …}`

#### GO-10.1.3 Указатель на структуру и доступ к полям
**Вопросы**
- [ ] Как обратиться к полю через указатель на структуру? · `go pointer to struct field access`
- [ ] Почему можно писать `p.Name`, а не `(*p).Name`? · `go automatic dereference struct pointer`
- [ ] Что делает `&User{Name: "Аня"}`? · `go &struct literal`
- [ ] Что будет при `p.Name`, если `p` — nil? · `nil struct pointer field access panic`
- [ ] Когда работают с указателем на структуру, а когда — со значением? · `go struct pointer vs value`

**Гуглить:** `golang struct pointer` · `go &T{} literal`

**Должен знать**
`p := &User{Name: "Аня"}` создаёт структуру и сразу берёт её адрес. Через указатель к полю обращаются той же точкой: `p.Name` — Go сам разыменует указатель. Если `p` — nil, обращение к полю — паника.
Указатель на структуру передают, когда её нужно изменить или когда она большая. Это один из самых частых видов указателей в Go.

**Термины**
- **`&T{…}`** — создать структуру и получить указатель на неё
- **автоматическое разыменование** — `p.Field` вместо `(*p).Field`

#### GO-10.1.4 Структура при присваивании и передаче
**Вопросы**
- [ ] Что происходит при присваивании структуры и передаче её в функцию? · `go struct copy on assignment`
- [ ] Функция изменила поле переданной структуры. Что увидит вызывающий? · `go modify struct in function`
- [ ] Как функции изменить структуру вызывающего? · `go pass struct pointer`
- [ ] Когда копирование структуры становится заметно дорогим? · `large struct copy cost`

**Гуглить:** `golang struct pass by value` · `go struct pointer receiver vs value`

**Должен знать**
Структура копируется целиком при присваивании и передаче: `b := a` — независимая копия всех полей, а функция, получившая структуру, меняет только свою копию. Чтобы изменить структуру вызывающего, передают указатель.
Копирование небольших структур дёшево и делает код безопаснее. Для больших (сотни байтов) или тех, что меняются, используют указатель.

**Термины**
- **копия структуры** — все поля копируются при присваивании и передаче

#### GO-10.1.5 Слайс или map внутри скопированной структуры
**Вопросы**
- [ ] Скопировали структуру, внутри которой слайс, и изменили элемент слайса в копии. Что будет с оригиналом? · `go copy struct with slice field shared`
- [ ] Почему копия структуры — «поверхностная»? · `shallow copy struct go`
- [ ] Что будет, если в копии сделать `append` к полю-слайсу? · `append to slice field in struct copy`
- [ ] Как сделать полную независимую копию структуры с полями-слайсами и map? · `deep copy struct go`
- [ ] Что будет с map внутри скопированной структуры? · `struct copy map field shared`

**Гуглить:** `go shallow copy struct` · `golang deep copy`

**Должен знать**
Копия структуры копирует поля как есть. Поле-слайс — это заголовок, поэтому копия получает тот же указатель на массив: изменение элемента через копию видно в оригинале. Поле-map — указатель на таблицу, поэтому map вообще общая. Это «поверхностная» копия.
`append` к полю-слайсу в копии поведёт себя как с любым слайсом: может записать в общий массив, может переехать. Независимую копию делают вручную: копируют слайсы и map по отдельности.

**Термины**
- **поверхностная копия** — копируются поля, но не данные, на которые они указывают
- **глубокая копия** — копируются и данные внутри полей

#### GO-10.1.6 Функция-конструктор NewX
**Вопросы**
- [ ] Зачем нужна функция-конструктор `NewUser`, если структуру можно создать литералом? · `go constructor function NewX`
- [ ] Что обычно возвращает конструктор: значение, указатель, признак ошибки? · `go constructor return pointer error`
- [ ] Как конструктор помогает проверить данные и заполнить поля по умолчанию? · `go constructor validation defaults`
- [ ] Чем это похоже на `__init__` в Python и чем отличается? · `python __init__ vs go constructor`
- [ ] Как не дать создать структуру в обход конструктора? · `go unexported fields force constructor`

**Гуглить:** `golang constructor pattern` · `go new function naming`

**Должен знать**
В языке Go нет конструкторов; вместо них пишут обычную функцию `NewUser(name string) (*User, error)`, которая проверяет данные, заполняет значения по умолчанию и создаёт map и слайсы внутри. Это то место, где «структуру с проверками» делают правильно.
Мост из Python: роль та же, что у `__init__`, но это просто функция. Чтобы структуру нельзя было собрать в обход проверок, её поля делают неэкспортируемыми.

**Термины**
- **конструктор** *(новое)* — функция `NewX`, создающая готовое к работе значение

#### GO-10.1.7 Анонимные структуры
**Вопросы**
- [ ] Как объявить структуру без имени прямо в коде: `p := struct{ X, Y int }{1, 2}`? · `go anonymous struct`

**Термины**

#### GO-10.1.8 Сравнение структур и структура как ключ map
**Вопросы**
- [ ] Можно ли сравнивать структуры через `==`? · `go compare structs`
- [ ] Когда структура может быть ключом map, а когда нет? · `go struct as map key comparable`
- [ ] Что будет, если в структуре есть поле-слайс, а её попробовать сравнить? · `struct with slice not comparable`
- [ ] Почему сравнение структур с указателями сравнивает адреса, а не данные? · `compare structs with pointer fields`

**Гуглить:** `golang struct comparison` · `go struct map key`

**Должен знать**
Структура сравнима, если сравнимы все её поля: тогда `==` сравнивает поля попарно, и такую структуру можно сделать ключом map — удобная замена составному ключу. Если хоть одно поле — слайс, map или функция, сравнение не скомпилируется.
Поля-указатели сравниваются по адресу: две структуры с указателями на одинаковые, но разные данные будут не равны.

**Термины**
- **сравнимая структура** — структура, у которой все поля сравнимы

#### GO-10.1.9 Изменение поля структуры, которая лежит в map
**Вопросы**
- [ ] Почему не компилируется `m["a"].Count++`, если в map лежат структуры? · `cannot assign to struct field in map`
- [ ] Как обойти: прочитать, изменить, записать обратно? · `go update struct in map`
- [ ] Когда удобнее хранить в map указатели на структуры? · `go map of struct pointers`
- [ ] Чем это отличается от слайса структур, где `s[0].Count++` работает? · `slice of struct modify field works`

**Гуглить:** `go cannot assign to struct field in map` · `golang map struct value update`

**Должен знать**
Элемент map нельзя адресовать (он может переехать), поэтому нельзя изменить и его поле: `m["a"].Count++` — ошибка компиляции. Обходной путь: `v := m["a"]; v.Count++; m["a"] = v`. Либо хранить указатели `map[string]*Item` — тогда `m["a"].Count++` меняет данные по указателю.
У слайса такой проблемы нет: `s[0].Count++` работает, потому что элемент слайса адресуем.

**Термины**
- **«прочитать — изменить — записать»** — способ обновить структуру в map

#### GO-10.1.11 Множество через map[T]struct{}
**Вопросы**
- [ ] Как сделать множество на map? · `go set implementation map struct{}`
- [ ] Почему `map[string]struct{}` лучше, чем `map[string]bool`? · `map struct{} vs map bool`
- [ ] Как добавить элемент, проверить наличие и удалить? · `go set add contains delete`
- [ ] Как посчитать пересечение двух множеств? · `go set intersection`
- [ ] Чем это похоже на `set` в Python и чего не хватает (нет готовых операций)? · `python set vs go map`

**Гуглить:** `golang set` · `go map[string]struct{}`

**Должен знать**
В языке Go нет готового множества, его делают на map: `seen := map[string]struct{}{}`; добавить — `seen[x] = struct{}{}`, проверить — `_, ok := seen[x]`, удалить — `delete(seen, x)`. Значение `struct{}` не занимает места и показывает, что важен только ключ.
`map[string]bool` тоже работает и чуть удобнее при проверке (`if seen[x]`), но тратит байт на значение. Операции вроде пересечения и объединения пишут циклом.

**Термины**
- **множество** *(новое)* — набор уникальных значений без порядка

#### GO-10.1.12 Печать структуры: %v, %+v, %#v, %T
**Вопросы**
- [ ] Чем отличаются `%v`, `%+v`, `%#v` при печати структуры? · `go printf %v %+v %#v struct`
- [ ] Что печатает `%T`? · `go printf %T`
- [ ] Как напечатается указатель на структуру через `%v`? · `go print pointer to struct &{}`
- [ ] Какой формат удобнее для отладки? · `go debug print struct`

**Гуглить:** `golang print struct fields` · `fmt verbs struct`

**Должен знать**
`%v` печатает значения полей `{Аня 30}`, `%+v` — с именами `{Name:Аня Age:30}`, `%#v` — как код на Go `main.User{Name:"Аня", Age:30}`, `%T` — имя типа. Указатель на структуру `%v` печатает как `&{Аня 30}`.
Для отладки обычно хватает `%+v`.

**Термины**
- **`%+v`** — печать структуры с именами полей

### GO-10.2 Структура в памяти

#### GO-10.2.1 Выравнивание
**Вопросы**
- [ ] Что такое выравнивание и зачем оно процессору? · `memory alignment explained`
- [ ] По каким адресам должно лежать `int64`, `int32`, `bool`? · `go alignment int64 int32 bool`
- [ ] Что будет, если процессору придётся читать значение с «неровного» адреса? · `unaligned memory access cost`
- [ ] Как узнать выравнивание типа (`unsafe.Alignof`)? · `go unsafe.Alignof`

**Гуглить:** `data structure alignment` · `golang memory alignment`

**Должен знать**
Процессор быстрее всего читает значение, если его адрес кратен его размеру: `int64` — по адресу, кратному 8, `int32` — кратному 4, `bool` — любому. Это и есть выравнивание. На некоторых процессорах невыровненное чтение вообще невозможно, на других — медленнее.
Компилятор сам раскладывает поля по выровненным адресам — иногда ценой пустых байтов между ними.

**Термины**
- **выравнивание** *(новое)* — требование, чтобы адрес значения был кратен определённому числу

#### GO-10.2.2 Паддинг и порядок полей
**Вопросы**
- [ ] Почему порядок полей меняет размер структуры? · `go struct padding field order`
- [ ] Сколько займёт `struct{ a bool; b int64; c bool }` и сколько — после перестановки полей? · `struct size 24 vs 16 reorder`
- [ ] Как упорядочить поля, чтобы структура стала меньше? · `order struct fields largest first`
- [ ] Когда это реально важно (миллионы значений в памяти)? · `struct padding matters when`
- [ ] Какой линтер находит такие места (`fieldalignment`)? · `go fieldalignment linter`

**Гуглить:** `golang struct padding` · `go fieldalignment`

**Должен знать**
Чтобы каждое поле было выровнено, компилятор вставляет пустые байты — паддинг. В `struct{ a bool; b int64; c bool }` после `a` идут 7 пустых байтов, после `c` — ещё 7: всего 24 байта. Если поставить `b` первым, а два `bool` рядом, выйдет 16.
Правило: поля от больших к меньшим. Заниматься этим стоит, когда таких структур миллионы; в обычном коде порядок полей выбирают по смыслу.

**Термины**
- **паддинг** *(новое)* — пустые байты между полями ради выравнивания

**Граница:** `unsafe.Sizeof` как способ проверить — одной строкой.

#### GO-10.2.3 Размер пустой структуры
**Вопросы**
- [ ] Почему `struct{}` занимает 0 байт и что тогда у неё за адрес? · `go zero size struct address`
- [ ] Сколько займёт `[1000]struct{}`? · `array of empty struct size`
- [ ] Почему пустое поле в конце структуры может увеличить её размер? · `zero size field at end of struct padding`

**Гуглить:** `go zero-sized types` · `empty struct final field padding`

**Должен знать**
У значений нулевого размера нет данных, поэтому Go может давать им один и тот же адрес; массив из тысячи пустых структур тоже весит 0 байт. Это и делает `struct{}` идеальным значением-сигналом.
Тонкость: пустое поле в самом конце структуры компилятор дополняет байтами, чтобы указатель на него не вёл за пределы структуры, — поэтому такие поля ставят в начало.

**Термины**
- **тип нулевого размера** — тип, значения которого не занимают памяти

### GO-10.3 Структура и JSON

#### GO-10.3.1 Формат JSON
**Вопросы**
- [ ] Что такое JSON и почему почти все сервисы обмениваются данными в нём? · `what is json`
- [ ] Какие типы значений есть в JSON (объект, массив, строка, число, `true`/`false`, `null`)? · `json data types`
- [ ] Почему в JSON нет комментариев и дат? · `json no comments no date type`
- [ ] Почему числа в JSON опасны для больших целых и денег? · `json number precision large integers`
- [ ] Что значит «закодировать» значение в JSON и «раскодировать» обратно (marshal/unmarshal)? · `marshal unmarshal meaning`

**Гуглить:** `json format explained` · `json number precision javascript 2^53`

**Должен знать**
JSON — текстовый формат данных: объекты `{"name": "Аня"}`, массивы `[1, 2]`, строки, числа, `true`/`false`, `null`. Его понимает любой язык, поэтому почти все сервисы и браузеры обмениваются данными именно в нём. Комментариев и дат в нём нет; даты передают строками.
Перевод значения программы в такой текст называют кодированием (marshal), обратно — раскодированием (unmarshal). Числа в JSON многие программы читают как `float64`, поэтому очень большие целые и деньги часто передают строкой.

**Термины**
- **JSON** *(новое)* — текстовый формат обмена данными
- **кодирование (marshal)** — перевод значения в формат для передачи или хранения

#### GO-10.3.2 Теги полей
**Вопросы**
- [ ] Что такое тег поля и как через него задать имя в JSON? · `go struct tags json`
- [ ] Как записывается тег: `json:"name"` в обратных кавычках? · `go struct tag syntax`
- [ ] Как исключить поле из JSON (`json:"-"`)? · `go json ignore field`
- [ ] Кто и как читает теги во время работы программы? · `go reflect struct tag`
- [ ] Где ещё встречаются теги (`db:"…"`, `validate:"…"`)? · `go struct tags db validate`

**Гуглить:** `golang struct tags` · `go json struct tag`

**Должен знать**
Тег — строка-подпись к полю: `Name string `json:"name"``. Компилятор её не использует, а библиотеки читают во время работы программы и настраивают по ней поведение: имя в JSON, имя столбца в базе, правила проверки. `json:"-"` исключает поле.
Пробелов вокруг двоеточия быть не должно — иначе тег молча не сработает; `go vet` такое ловит.

**Термины**
- **тег поля** *(новое)* — строка-подпись поля для библиотек

**Граница:** пакет `reflect`, который их читает, — одной фразой.

#### GO-10.3.3 encoding/json: Marshal и Unmarshal
**Вопросы**
- [ ] Как превратить структуру в JSON и обратно? · `golang json marshal unmarshal`
- [ ] Почему в `json.Unmarshal` передают указатель? · `json.Unmarshal pointer why`
- [ ] Что будет с полями JSON, которых нет в структуре, и с полями структуры, которых нет в JSON? · `go json unknown fields missing fields`
- [ ] Как красиво отформатировать JSON (`MarshalIndent`)? · `go json MarshalIndent`
- [ ] Как разобрать JSON в `map[string]any`, если структура заранее неизвестна? · `go json unmarshal into map`

**Гуглить:** `go encoding/json` · `go by example json`

**Должен знать**
`data, err := json.Marshal(u)` превращает значение в байты JSON; `err := json.Unmarshal(data, &u)` заполняет структуру из JSON — по указателю, как `fmt.Scan`. Поля сопоставляются по тегам (или по именам без учёта регистра).
Лишние поля JSON молча игнорируются, отсутствующие оставляют нулевые значения. Оба вызова возвращают признак ошибки — его проверяют.

**Термины**
- **`json.Marshal`** — значение → JSON
- **`json.Unmarshal`** — JSON → значение по указателю

**Позже:** второе возвращаемое значение — ошибка — GO-13.1.1; тип `any` — GO-12.2.3.

#### GO-10.3.4 Неэкспортируемые поля и JSON
**Вопросы**
- [ ] Почему поле с маленькой буквы не попадает в JSON? · `go json unexported fields ignored`
- [ ] Поможет ли тег `json:"name"` у поля `name`? · `json tag on unexported field`
- [ ] Как это связано с экспортом из GO-5.1.3? · `go reflect cannot access unexported`
- [ ] Почему этот баг тихий и как его заметить? · `go json empty object {}`

**Гуглить:** `golang json lowercase fields` · `go json unexported`

**Должен знать**
`encoding/json` — другой пакет, а неэкспортируемые поля другим пакетам не видны. Поэтому поле `name` (со строчной) не попадёт в JSON и не заполнится при разборе — даже с тегом. Ошибки не будет: получится `{}`.
Поэтому поля для JSON всегда с заглавной, а нужное имя в JSON задают тегом.

**Термины**
- **невидимое поле** — неэкспортируемое поле, которое не видят другие пакеты

#### GO-10.3.5 omitempty и нулевые значения
**Вопросы**
- [ ] Что делает `omitempty`? · `go json omitempty`
- [ ] Какие значения считаются «пустыми» (0, `""`, `false`, nil, пустые слайс и map)? · `omitempty empty values list`
- [ ] Почему `omitempty` не убирает пустую вложенную структуру и что делает `omitzero` (Go 1.24)? · `go 1.24 omitzero`
- [ ] Как отличить «0» от «не передали», если `omitempty` выбросил ноль? · `omitempty zero value ambiguity pointer`
- [ ] Что изменилось с переходом `encoding/json` на новую реализацию в Go 1.27? · `go encoding/json v2`

**Гуглить:** `golang omitempty` · `go 1.24 omitzero` · `encoding/json/v2`

**Должен знать**
`json:"age,omitempty"` не пишет поле, если значение «пустое»: 0, `""`, `false`, nil, слайс или map нулевой длины. Пустую вложенную структуру `omitempty` не убирает; для этого с Go 1.24 есть `omitzero`, который пропускает любое нулевое значение. С Go 1.27 `encoding/json` работает на новой реализации (v2) — тонкости `omitempty` сверяй с документацией своей версии.
Ловушка: с `omitempty` настоящий ноль неотличим от «не передали». Когда разница важна, поле делают указателем: nil — «нет значения», указатель на 0 — «ноль».

**Термины**
- **`omitempty`** — не писать поле с «пустым» значением
- **`omitzero`** — не писать поле с нулевым значением (Go 1.24)

### GO-10.4 Сортировка

#### GO-10.4.1 slices.Sort и slices.SortFunc
**Вопросы**
- [ ] Как отсортировать слайс чисел или строк одной строкой? · `go slices.Sort`
- [ ] Как отсортировать слайс структур по полю `Name`? · `go slices.SortFunc struct field`
- [ ] Что должна возвращать функция сравнения (отрицательное, 0, положительное)? · `slices.SortFunc cmp function`
- [ ] Как удобно сравнивать через `cmp.Compare` и `strings.Compare`? · `go cmp.Compare`
- [ ] Как отсортировать по двум полям (сначала по городу, потом по имени)? · `go sort by multiple fields cmp.Or`
- [ ] Как отсортировать по убыванию? · `go sort descending slices.SortFunc`

**Гуглить:** `golang slices.SortFunc` · `go cmp.Or multiple fields`

**Должен знать**
`slices.Sort(s)` сортирует слайс сравнимых по порядку значений на месте. Для структур — `slices.SortFunc(users, func(a, b User) int { return cmp.Compare(a.Name, b.Name) })`: функция возвращает отрицательное число, если `a` раньше `b`, 0 — если равны, положительное — если позже.
По нескольким полям удобно `cmp.Or(cmp.Compare(a.City, b.City), cmp.Compare(a.Name, b.Name))`. По убыванию — поменять `a` и `b` местами. Это частая задача на лайвкодинге.

**Термины**
- **функция сравнения** — возвращает знак порядка двух элементов
- **`cmp.Compare`** — готовое сравнение двух значений

#### GO-10.4.2 sort.Slice
**Вопросы**
- [ ] Как отсортировать через `sort.Slice` и чем его функция отличается от `SortFunc` (возвращает `bool`)? · `go sort.Slice example`
- [ ] Почему в старом коде встречается `sort.Slice`, а в новом — `slices.SortFunc`? · `sort.Slice vs slices.SortFunc`
- [ ] Почему `sort.Slice` медленнее и менее безопасен по типам? · `sort.Slice performance any`

**Гуглить:** `golang sort.Slice` · `sort package vs slices`

**Должен знать**
`sort.Slice(s, func(i, j int) bool { return s[i].Name < s[j].Name })` — старый способ: функция получает номера и отвечает «меньше ли». Он встречается во множестве существующего кода, поэтому читать его нужно уметь.
В новом коде (Go 1.21+) пишут `slices.SortFunc`: он проверяет типы при компиляции и работает быстрее.

**Термины**
- **`sort.Slice`** — старая сортировка с функцией «меньше» по номерам

#### GO-10.4.3 Устойчивая сортировка
**Вопросы**
- [ ] Что такое устойчивая сортировка и когда она нужна? · `stable sort explained`
- [ ] Сохраняет ли `slices.SortFunc` порядок равных элементов? · `slices.SortFunc not stable`
- [ ] Чем `slices.SortStableFunc` отличается? · `go slices.SortStableFunc`
- [ ] Как получить сортировку «по городу, а внутри — в исходном порядке»? · `stable sort secondary order`

**Гуглить:** `stable sorting algorithm` · `go SortStableFunc`

**Должен знать**
Устойчивая сортировка не меняет взаимный порядок элементов, которые при сравнении равны. Обычная `slices.SortFunc` этого не гарантирует. `slices.SortStableFunc` гарантирует — нужна, когда исходный порядок что-то значит (например, список уже отсортирован по времени, и сортируешь его по городу).

**Термины**
- **устойчивая сортировка** *(новое)* — равные элементы сохраняют исходный порядок

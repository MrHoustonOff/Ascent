## GO-2. Переменные и базовые типы

### GO-2.1 Переменная

#### GO-2.1.1 Переменная в Go
**Вопросы**
- [ ] Чем переменная в Go отличается от переменной в Python? · `go variable vs python variable`
- [ ] Что значит «переменная — это кусок памяти определённого размера»? · `go variable memory location`
- [ ] Почему у переменной в Go тип фиксирован навсегда, а в Python имя можно привязать к объекту другого типа? · `static typing vs dynamic typing`
- [ ] Почему `x = 5`, а потом `x = "hi"` в Go не скомпилируется? · `go cannot use string as int value`
- [ ] Как напечатать адрес переменной (`&x` с `%p`) и убедиться, что после присваивания он не меняется? · `go print variable address %p`

**Гуглить:** `go variables explained` · `python names vs go variables` · `statically typed language`

**Должен знать**
В Go переменная — это место в памяти фиксированного размера, в котором лежит само значение. У переменной один тип на всё время её жизни, и компилятор проверяет это ещё до запуска. Присваивание кладёт новое значение в то же место.
Мост из Python: там переменная — имя-ярлык, привязанное к объекту в куче; присваивание просто перевешивает ярлык на другой объект, и тип у имени может меняться. Отсюда половина будущих сюрпризов «что выведет код».

**Термины**
- **переменная** — именованный кусок памяти, хранящий значение одного типа
- **статическая типизация** — тип известен и проверяется при компиляции

**Граница:** где именно лежит переменная — на стеке или в куче — решает компилятор; это GO-21.1.

#### GO-2.1.2 Объявление через var
**Вопросы**
- [ ] Как выглядит объявление `var x int` и `var x int = 5`? · `go var declaration`

**Должен знать**
`var имя тип` объявляет переменную; значение можно сразу задать через `=`. Если значение указано, тип можно опустить — компилятор возьмёт его из значения. Несколько переменных объявляют группой в скобках `var ( … )`.

**Термины**
- **объявление** — указание компилятору, что есть переменная с таким именем и типом

#### GO-2.1.3 Короткое объявление :=
**Вопросы**
- [ ] Чем `var x int` отличается от `x := 0`? · `go var vs short variable declaration`
- [ ] Где нельзя использовать `:=` (вне функции)? · `go := outside function error`
- [ ] Чем `:=` отличается от `=`? Что будет, если написать `:=` для уже объявленной переменной? · `no new variables on left side of :=`

- [ ] Когда в `a, err := f()` можно повторно использовать `:=` с уже существующим `err`? · `go := redeclare at least one new variable`

**Гуглить:** `golang short variable declaration` · `go type inference` · `go no new variables on left side`

**Должен знать**
`x := 0` — короткое объявление: оно одновременно объявляет переменную и присваивает значение, а тип выводит из правой части. Работает только внутри функций. `=` — просто присваивание уже существующей переменной.
При `:=` слева должна быть хотя бы одна новая переменная; остальные будут просто присвоены. Вывод типа берёт тип по умолчанию: целое число → `int`, дробное → `float64`.

**Термины**
- **короткое объявление** *(новое)* — `:=`: объявить и присвоить, тип выводится сам
- **вывод типа** *(новое)* — компилятор определяет тип переменной по значению

#### GO-2.1.4 Нулевые значения
**Вопросы**
- [ ] Какие нулевые значения у `int`, `float64`, `string`, `bool`? · `go zero values`
- [ ] Почему в Go нет «неинициализированных» переменных с мусором внутри, как в C? · `go zero value guarantee`
- [ ] Как отличить «пустую строку» от «значения нет», если нулевое значение строки — `""`? · `go distinguish zero value from unset`

- [ ] Чем нулевое значение отличается от `None` в Python? · `go zero value vs python none`

**Гуглить:** `golang zero value` · `make the zero value useful go proverb`

**Должен знать**
Любая переменная в Go, объявленная без значения, сразу получает нулевое значение своего типа: `0` для чисел, `""` для строк, `false` для `bool`. Мусора из памяти не бывает никогда.
Обратная сторона: нулевое значение — это настоящее значение, а не «пусто». Если нужно отличать «ноль» от «не задано», это приходится делать отдельно. Аналога `None` для чисел и строк в Go нет.

**Термины**
- **нулевое значение** *(новое)* — значение, которое переменная получает, если её не инициализировали

**Граница:** нулевые значения сложных типов — по мере их появления.

#### GO-2.1.5 Присваивание и копирование значений
**Вопросы**
- [ ] Что происходит в памяти при `b := a`? Изменится ли `a`, если изменить `b`? · `go assignment copies value`
- [ ] Почему в Python после `b = a` для списка изменение `b` видно через `a`, а в Go для `int` — нет? · `python assignment reference same object`
- [ ] Что копирует присваивание в Go: значение целиком или «ссылку»? · `go everything is passed by value`
- [ ] Сколько стоит копирование и от чего это зависит? · `go copy cost value size`

**Гуглить:** `go assignment semantics copy` · `python assignment does not copy` · `go pass by value`

**Должен знать**
Присваивание в Go копирует значение: `b := a` создаёт отдельный кусок памяти с такой же копией байтов. Дальше `a` и `b` живут независимо — изменение одной не видно через другую. Стоимость копии зависит только от размера значения.
Мост из Python: там `b = a` не копирует ничего, а вешает второй ярлык на тот же объект. Для чисел, которые нельзя поменять на месте, это незаметно, а для списков — классическая ловушка. В Go копируется всегда, а «общие» данные появятся только там, где внутри значения лежит адрес.

**Термины**
- **копирование значения** — присваивание создаёт независимую копию байтов

**Граница:** типы, внутри которых лежит адрес на общие данные, — по мере их появления.

### GO-2.2 Целые числа в Go

#### GO-2.2.1 Целые типы фиксированного размера: int8…int64, uint8…uint64
**Вопросы**
- [ ] Какие целые типы есть в Go и сколько байтов занимает каждый? · `go integer types sizes`
- [ ] Какой диапазон у `int8`, `int16`, `int32`, `int64`? Свяжи с формулой из ФУНД-2.2. · `go int8 int16 int32 int64 range`
- [ ] Где в `math` лежат готовые предельные значения (`math.MaxInt32`, `math.MinInt64`)? · `golang math.MaxInt64`

**Гуглить:** `golang integer types` · `go int range table`

**Должен знать**
Число в названии типа — количество бит: `int8` занимает 1 байт, `int64` — 8. Знаковые типы (`int…`) хранят числа в дополнительном коде, беззнаковые (`uint…`) — только неотрицательные. Предельные значения есть готовыми в пакете `math`.
Фиксированный размер выбирают, когда он важен: формат файла, обмен данными по сети, экономия памяти на миллионах значений. В обычном коде берут `int`.

**Термины**
- **`int8`…`int64`** — знаковые целые размером 1, 2, 4, 8 байт
- **`uint8`…`uint64`** — беззнаковые целые тех же размеров

**Граница:** `uintptr` — знать, что есть, не использовать.

#### GO-2.2.2 Типы int и uint
**Вопросы**
- [ ] Сколько байтов занимает `int` и от чего это зависит? · `go int size 32 or 64 bit`

`int` — выбор по умолчанию: в нём длины, номера элементов, счётчики. `uint` берут редко: разница двух беззнаковых чисел, которая должна быть отрицательной, молча становится огромным положительным числом.

#### GO-2.2.3 byte и rune
**Вопросы**
- [ ] Что такое `byte` и `rune` и почему у них такие имена? · `go byte rune explained`
- [ ] Каким типам они равны (`uint8` и `int32`) и почему это одно и то же, а не просто похожее? · `go byte alias uint8 rune alias int32`
- [ ] Почему для code point нужно 32 бита? · `why rune is int32 unicode`
- [ ] Что хранит `'Ж'` в одинарных кавычках и какой у него тип? · `go rune literal single quotes`
- [ ] Как напечатать руну как символ (`%c`) и как число (`%d`, `%U`)? · `go printf %c %U rune`

**Гуглить:** `golang byte vs rune` · `go rune literal` · `go blog strings bytes runes`

**Должен знать**
`byte` — другое имя `uint8`: один байт, например кусочек UTF-8. `rune` — другое имя `int32`: один code point Unicode, ему нужно до 21 бита, поэтому берут 32. Имена ничего не добавляют к типам, они лишь говорят читателю, что значение — байт или символ.

**Термины**
- **`byte`** — то же, что `uint8`; один байт
- **rune** *(новое)* — то же, что `int32`; один code point Unicode
- **литерал руны** — символ в одинарных кавычках, `'a'`

#### GO-2.2.4 Арифметические операции и целочисленное деление
**Вопросы**
- [ ] Что вернёт `7 / 2` в Go и почему не `3.5`? · `go integer division truncates`
- [ ] Что вернёт `-7 / 2` и `-7 % 2` в Go, а что — в Python (`//`, `%`)? Почему ответы разные? · `go vs python negative integer division modulo`
- [ ] Как получить дробный результат деления двух целых? · `go divide ints get float`
- [ ] Какие арифметические операции есть в Go и есть ли возведение в степень `**`? · `go power operator math.Pow`
- [ ] Как проверить чётность числа через `%`? · `go check even odd modulo`

**Гуглить:** `golang integer division` · `go modulo negative numbers` · `truncated vs floored division`

**Должен знать**
Деление двух целых в Go — целочисленное: дробная часть отбрасывается, `7 / 2 == 3`. Округление идёт к нулю, поэтому `-7 / 2 == -3`, а остаток `%` берёт знак делимого: `-7 % 2 == -1`. В Python `//` округляет вниз, поэтому там `-4` и `1` — частая ловушка при переносе кода.
Чтобы получить дробный результат, оба значения переводят в `float64`. Оператора `**` нет — есть `math.Pow` для дробных чисел.

**Термины**
- **целочисленное деление** — деление с отбрасыванием дробной части
- **остаток от деления** — `%`; в Go имеет знак делимого

**Граница:** приоритеты всех операций — запоминать не нужно, ставь скобки.

#### GO-2.2.5 Деление целого на ноль и паника

#### GO-2.2.7 Инкремент и составное присваивание
**Вопросы**
- [ ] Как записать увеличение на 1 в Go? · `go increment operator`

**Термины**
- **инкремент** — увеличение на 1, `x++`
- **составное присваивание** — `+=`, `-=` и другие

### GO-2.5 Битовые операции

#### GO-2.5.1 Битовые И, ИЛИ, исключающее ИЛИ; маски
**Вопросы**
- [ ] Что делают `&`, `|`, `^` над двумя числами? Посчитай `12 & 10`, `12 | 10`, `12 ^ 10` в двоичной записи. · `bitwise and or xor examples`
- [ ] Чем `&` отличается от `&&`? · `bitwise and vs logical and`
- [ ] Что такое маска и как проверить, что нужный бит установлен (`flags & mask != 0`)? · `bitmask check bit set`

**Должен знать**
Битовые операции работают с каждым битом отдельно: `&` — 1 только там, где 1 в обоих числах; `|` — где хотя бы в одном; `^` — где ровно в одном. Унарный `^x` в Go переворачивает все биты (в Python это `~`).

- **маска** *(новое)* — число, которое выделяет нужные биты другого числа

#### GO-2.5.2 Битовые сдвиги
**Вопросы**
- [ ] Что делают `<<` и `>>`? Посчитай `1 << 3` и `40 >> 2`. · `bit shift left right examples`

**Должен знать**

#### GO-2.5.3 Сброс битов &^ и проверка степени двойки
**Вопросы**
- [ ] Что делает `&^` и чем `x &^ mask` отличается от `x & ^mask`? · `go and not operator &^`
- [ ] Как сбросить нужный бит в флагах? · `clear bit go &^=`
- [ ] Как проверить, что число — степень двойки, одной строкой (`n > 0 && n&(n-1) == 0`)? · `check power of two n & (n-1)`

**Гуглить:** `golang &^ bit clear` · `power of two bit trick` · `brian kernighan bit count`

**Должен знать**
`&^` — «И НЕ»: `x &^ mask` обнуляет в `x` те биты, где в маске единицы. Это короче и понятнее, чем `x & ^mask`, хотя результат тот же.

- [ ] Почему нулевое значение перечисления лучше делать «неизвестным» состоянием? · `go enum zero value unknown`

**Гуглить:** `golang iota` · `go enum pattern` · `iota bitmask flags`

**Должен знать**
`iota` — счётчик внутри блока `const ( … )`: в первой строке 0, в каждой следующей на 1 больше. Строки без выражения повторяют предыдущее, поэтому `A = iota; B; C` дают 0, 1, 2. Так в Go делают перечисления.
С `1 << iota` получаются флаги-степени двойки для масок. Хорошая практика: значение 0 — «не задано», чтобы нулевое значение переменной не выглядело как осмысленный вариант.

**Термины**
- **iota** *(новое)* — счётчик строк в блоке констант
- **перечисление** — набор именованных вариантов значения

### GO-2.9 Свои типы

#### GO-2.9.1 Свои типы на основе существующих
**Вопросы**
- [ ] Что делает `type Celsius float64`? · `go type definition`
- [ ] Можно ли сложить значение типа `Celsius` и `float64` без преобразования? Почему? · `go defined type mismatched types`
- [ ] Какую ошибку предотвращают свои типы (`UserID` против `OrderID`)? · `go defined types type safety`
- [ ] Как привести `Celsius` к `float64` и обратно? · `go convert defined type underlying type`
- [ ] Что такое базовый тип и что новый тип у него берёт? · `go underlying type`

**Гуглить:** `golang type definition` · `go named types` · `go underlying type`

**Должен знать**
`type Celsius float64` создаёт новый тип: устроен в памяти как `float64` (это его базовый тип) и поддерживает те же операции, но для компилятора это другой тип. Смешать `Celsius` и `float64` без явного преобразования нельзя.
В этом и смысл: компилятор не даст передать градусы туда, где ждут метры, или ID заказа вместо ID пользователя. Преобразование между типом и его базовым типом — обычное `float64(c)`.

**Термины**
- **определение типа** — `type Новый Базовый`: новый тип с тем же устройством
- **базовый тип** — тип, на котором построен новый тип

#### GO-2.9.2 Псевдонимы типов
**Вопросы**
- [ ] Чем `type Celsius float64` отличается от `type Celsius = float64`? · `go type alias vs type definition`
- [ ] Почему `byte` и `rune` — это псевдонимы? · `byte is alias for uint8`
- [ ] Можно ли сложить псевдоним и исходный тип без преобразования? · `go type alias interchangeable`
- [ ] Зачем псевдонимы появились в Go (перенос типа между пакетами)? · `go type alias motivation refactoring`

**Гуглить:** `golang type alias` · `go 1.9 type aliases`

**Должен знать**
`type A = B` — псевдоним: просто второе имя того же типа. `A` и `B` полностью взаимозаменяемы, никакого преобразования не нужно. Так устроены `byte` (= `uint8`) и `rune` (= `int32`).
`type A B` без знака равенства — новый, отдельный тип. В обычном коде нужен почти всегда он; псевдонимы используют в основном при переносе кода между пакетами.

**Термины**
- **псевдоним** *(новое)* — `type A = B`, другое имя того же типа

**Граница:** редкие формы псевдонимов — не нужны.

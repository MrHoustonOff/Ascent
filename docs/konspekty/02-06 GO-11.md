## GO-11. Методы, встраивание и время

### GO-11.1 Методы

#### GO-11.1.1 Метод
**Вопросы**
- [ ] Что такое метод и чем он отличается от функции? · `go methods tour`
- [ ] Как объявить метод `func (u User) Greet() string`? · `golang method declaration`
- [ ] Чем `u` в скобках перед именем метода похоже на `self` в Python и чем отличается (явный тип, любое имя)? · `go receiver vs python self`
- [ ] Почему метод можно объявить только в том же пакете, что и тип? · `cannot define new methods on non-local type`
- [ ] Как добавить свои методы к типу из стороннего пакета (свой тип на его основе)? · `go add methods to external type`
- [ ] Как принято называть эту переменную (одна-две буквы, не `self`)? · `go receiver naming convention`

**Гуглить:** `golang methods` · `go receiver name convention` · `go methods on external types`

**Должен знать**
Метод — функция, привязанная к типу: `func (u User) Greet() string { … }`, вызывается через точку `u.Greet()`. В скобках перед именем — значение, для которого метод вызван. Это тот же `self` из Python, только объявлен явно, с типом, и называют его коротко по типу (`u`, `s`), а не `self`.
Метод можно объявить только у типа из своего пакета. Чтобы добавить методы к чужому типу, объявляют свой тип на его основе.

**Термины**
- **метод** *(новое)* — функция, привязанная к типу и вызываемая через точку

**Позже:** второй способ «расширить» чужой тип — GO-11.2.1.

#### GO-11.1.2 Получатель по значению
**Вопросы**
- [ ] Что получает метод с получателем по значению: копию или оригинал? · `go value receiver copy`
- [ ] Почему изменение поля в таком методе не видно снаружи? · `go value receiver cannot modify`
- [ ] Когда получатель по значению — хороший выбор (маленький тип, только чтение)? · `when to use value receiver`
- [ ] Напиши `func (c Counter) Inc()` и убедись, что счётчик не растёт. · `value receiver increment bug`

**Гуглить:** `golang value receiver` · `go value vs pointer receiver`

**Должен знать**
Получатель по значению — копия: метод работает со своей копией значения, как функция со своим параметром. Изменения полей внутри него вызывающий не увидит, поэтому `func (c Counter) Inc() { c.n++ }` ничего не меняет.
Такой получатель подходит для маленьких типов, которые метод только читает.

**Термины**
- **получатель** *(новое)* — значение, для которого вызывается метод
- **получатель по значению** — метод получает копию

#### GO-11.1.3 Получатель по указателю
**Вопросы**
- [ ] Как объявить метод с получателем по указателю `func (c *Counter) Inc()`? · `go pointer receiver`
- [ ] Почему такой метод может изменить значение? · `pointer receiver modify struct`
- [ ] Почему большие структуры передают по указателю даже в методах, которые только читают? · `pointer receiver large struct performance`
- [ ] Что будет, если вызвать такой метод у nil? · `pointer receiver nil call`

**Гуглить:** `golang pointer receiver` · `go tour pointer receivers`

**Должен знать**
Получатель по указателю `func (c *Counter) Inc() { c.n++ }` получает адрес значения, поэтому метод меняет оригинал. Ещё один плюс — не копируется большая структура.
Это самый частый вид получателя для структур с состоянием.

**Термины**
- **получатель по указателю** — метод получает адрес значения и может его менять

#### GO-11.1.4 Автоматическое взятие адреса при вызове метода
**Вопросы**
- [ ] Почему у значения можно вызвать метод с получателем-указателем? · `go automatic address method call`
- [ ] Во что превращает компилятор вызов `c.Inc()`, если `c` — переменная? · `c.Inc() becomes (&c).Inc()`
- [ ] Почему для элемента map или результата функции это не работает? · `cannot call pointer method on map element`
- [ ] Работает ли обратное: вызвать метод со значением-получателем у указателя? · `call value method on pointer go`

**Гуглить:** `go method call addressable` · `go spec calls method sets`

**Должен знать**
Если `c` — переменная, вызов `c.Inc()` с получателем-указателем компилятор сам превращает в `(&c).Inc()`. Обратное тоже работает: у указателя можно вызвать метод с получателем по значению — Go сам разыменует.
Но взять адрес можно только у адресуемого значения. Элемент map и результат вызова функции адреса не имеют, поэтому `m["a"].Inc()` с получателем-указателем не скомпилируется.

**Термины**
- **адресуемое значение** — значение, у которого можно взять адрес: переменная, элемент слайса, поле

#### GO-11.1.5 Какой получатель выбрать
**Вопросы**
- [ ] Как выбрать, какой получатель нужен методу? · `go choose value or pointer receiver`
- [ ] Почему все методы одного типа лучше делать с одинаковым видом получателя? · `consistent receiver type go`
- [ ] Почему тип, внутри которого есть защищённое от копирования состояние, нельзя копировать и нужен указатель? · `go copying value with internal state`
- [ ] Почему для маленьких неизменяемых значений (`time.Time`) берут значение? · `time.Time value receiver`

**Гуглить:** `go code review comments receiver type` · `golang receiver choice`

**Должен знать**
Указатель — если метод меняет значение, если тип большой, если копировать значение нельзя по смыслу. Значение — если тип маленький и неизменяемый по смыслу, как `time.Time`. Если хотя бы одному методу нужен указатель, обычно все методы типа делают с указателем: так тип ведёт себя предсказуемо.
В сомнениях выбирай указатель.

**Термины**
- **единообразие получателей** — все методы типа с одним видом получателя

**Позже:** как вид получателя влияет на то, какие методы есть у типа, — GO-12.1.3.

#### GO-11.1.6 Методы у любого своего типа
**Вопросы**
- [ ] Можно ли объявить метод у типа на основе `int`? · `go method on named int type`
- [ ] А у самого `int` или у типа из чужого пакета? · `cannot define methods on int`
- [ ] Напиши тип `Celsius` с методом `Fahrenheit()`. · `go custom type methods example`
- [ ] Как добавить метод к слайсу или map (свой тип `type Users []User`)? · `go methods on slice type`

**Гуглить:** `golang methods on non-struct types` · `go named types methods`

**Должен знать**
Метод можно объявить у любого своего типа, не только у структуры: `type Celsius float64` и `func (c Celsius) Fahrenheit() float64`. Так же — у своих типов на основе слайса или map: `type Users []User` с методом `Find`.
У самого `int` или у чужого типа методы объявить нельзя — только у своего типа на их основе. Именно так устроен `time.Duration`.

**Термины**
- **методы своего типа** — методы у типа, объявленного в своём пакете

#### GO-11.1.7 Метод на nil-указателе
**Вопросы**
- [ ] Что будет при вызове метода у nil-указателя? · `go method on nil pointer receiver`
- [ ] Когда такой вызов работает, а когда паникует? · `nil receiver works if no dereference`
- [ ] Как написать метод, который корректно работает и для nil (пустое дерево, пустой список)? · `go nil receiver idiom tree`

**Гуглить:** `golang nil receiver` · `go methods on nil pointers`

**Должен знать**
Вызвать метод с получателем-указателем у nil можно: метод просто получит nil. Паника случится, только если внутри он обратится к полям. Поэтому метод может сам проверить `if t == nil { return 0 }` и работать с «пустым» значением — так часто пишут для деревьев и списков.

**Термины**
- **nil-получатель** — метод вызван у nil-указателя

#### GO-11.1.8 Метод как значение
**Вопросы**
- [ ] Что получится в `f := u.Greet` и как это вызвать? · `go method value`
- [ ] Когда фиксируется получатель: при создании `f` или при вызове? · `method value receiver evaluated`
- [ ] Чем `User.Greet` (метод как функция) отличается от `u.Greet`? · `go method expression vs method value`
- [ ] Где это удобно (передать метод как функцию-обработчик)? · `pass method as function go`

**Гуглить:** `golang method values` · `go method expressions`

**Должен знать**
`f := u.Greet` — метод как значение: функция, к которой уже привязан получатель `u`; вызывают `f()`. Получатель фиксируется в момент создания: для получателя по значению копируется сам `u`, для указателя — адрес.
`User.Greet` — метод как обычная функция, где получатель — первый аргумент: `User.Greet(u)`. Метод-значение удобно передавать туда, где ждут функцию.

**Термины**
- **метод-значение** — `x.M`, функция с привязанным получателем

### GO-11.2 Встраивание

#### GO-11.2.1 Встраивание
**Вопросы**
- [ ] Что такое встраивание и как его записать (тип поля без имени)? · `go struct embedding`
- [ ] Как поля встроенной структуры становятся доступны снаружи? · `go embedded struct field access`
- [ ] Как обратиться к встроенной структуре целиком (по имени её типа)? · `access embedded struct by type name`
- [ ] Как встраивание помогает «расширить» тип из чужого пакета? · `go embed external type add methods`

**Гуглить:** `golang embedding` · `effective go embedding`

**Должен знать**
Встраивание — поле без имени, только с типом: `type Admin struct { User; Level int }`. Встроенная структура — обычное поле, его имя совпадает с именем типа (`a.User`), но её поля и методы доступны и напрямую: `a.Name`.
Так собирают тип из готовых частей и добавляют свои методы к чужому типу, не копируя его код.

**Термины**
- **встраивание** *(новое)* — включение типа в структуру без имени поля

#### GO-11.2.2 Продвижение полей и методов
**Вопросы**
- [ ] Что значит «продвижение» полей и методов? · `go promoted fields methods`
- [ ] Чей получатель у продвинутого метода: внешней или встроенной структуры? · `promoted method receiver is embedded`
- [ ] Видит ли метод встроенной структуры поля внешней? · `embedded method cannot access outer fields`
- [ ] Как продвижение работает при нескольких уровнях встраивания? · `go nested embedding promotion`

**Гуглить:** `golang promoted methods` · `go embedding method receiver`

**Должен знать**
Поля и методы встроенного типа «продвигаются» на уровень внешней структуры: `a.Greet()` — это на самом деле `a.User.Greet()`. Получатель такого метода — встроенный `User`, а не `Admin`; метод ничего не знает о внешней структуре и не видит её полей.
Продвижение работает и через несколько уровней встраивания.

**Термины**
- **продвижение** *(новое)* — поля и методы встроенного типа доступны напрямую у внешней структуры

#### GO-11.2.3 Встраивание против наследования
**Вопросы**
- [ ] Почему встраивание — это не наследование? · `go embedding vs inheritance`
- [ ] Можно ли передать `Admin` туда, где ждут `User`? · `go embedded type not subtype`
- [ ] Почему метод встроенного типа не может вызвать «переопределённый» метод внешнего? · `go no virtual methods embedding`
- [ ] Как в Python работает наследование и `super()`, и чего из этого в Go нет? · `python inheritance super method resolution`
- [ ] Что значит «композиция вместо наследования»? · `composition over inheritance`

**Гуглить:** `go is not object oriented inheritance` · `composition over inheritance` · `go faq inheritance`

**Должен знать**
Внешне похоже на наследование, но это другое. `Admin` не является `User`: передать `Admin` туда, где ждут `User`, нельзя — только `a.User`. Нет и «переопределения»: если метод `User` вызывает другой свой метод, вызовется метод `User`, даже если у `Admin` есть метод с тем же именем.
Мост из Python: там класс-наследник подменяет методы родителя, и `self` указывает на наследника. В Go встраивание — просто удобная композиция: один тип собран из других. Общее поведение разных типов в Go описывают иначе — об этом следующий блок.

**Термины**
- **наследование** *(новое)* — механизм классов, где наследник является родителем и подменяет его методы; в Go его нет
- **композиция** — тип собран из других типов

**Позже:** общее поведение разных типов — GO-12.1.1.

#### GO-11.2.4 Одинаковые имена на разных уровнях встраивания
**Вопросы**
- [ ] Что будет, если у внешней и встроенной структуры есть методы с одним именем? · `go embedding shadowing method`
- [ ] Как вызвать метод встроенной структуры, если внешний его скрывает? · `call embedded method explicitly`
- [ ] Что будет, если два встроенных типа на одном уровне имеют поле с одним именем? · `go ambiguous selector embedding`

**Гуглить:** `golang ambiguous selector` · `go embedding name conflict`

**Должен знать**
Ближайший уровень побеждает: если у `Admin` есть свой `Greet`, `a.Greet()` вызовет его, а метод `User` останется доступен как `a.User.Greet()`. Если же одно имя есть у двух встроенных типов на одном уровне, обращение к нему без уточнения — ошибка компиляции `ambiguous selector`.

**Термины**
- **скрытие имени** — имя внешнего уровня скрывает такое же имя встроенного

#### GO-11.2.5 Встраивание указателя на тип
**Вопросы**
- [ ] Чем `struct { *User }` отличается от `struct { User }`? · `go embed pointer type`
- [ ] Что будет при обращении к продвинутому полю, если встроенный указатель — nil? · `embedded nil pointer panic`

**Должен знать**

### GO-11.3 Время: пакет time

#### GO-11.3.1 time.Time и time.Now
**Вопросы**
- [ ] Что хранит `time.Time` и как получить текущий момент? · `golang time.Now`
- [ ] Как сравнить два момента (`Before`, `After`, `Equal`) и почему не `==`? · `go time compare Equal vs ==`
- [ ] Как прибавить к моменту час (`Add`) и посчитать разницу (`Sub`)? · `go time Add Sub`
- [ ] Какое нулевое значение у `time.Time` и как его проверить (`IsZero`)? · `go time zero value IsZero`
- [ ] Как получить время в UTC? · `go time UTC`

**Гуглить:** `golang time package` · `go time.Time Equal`

**Должен знать**
`time.Time` — момент времени (с часовым поясом), `time.Now()` — текущий. Сравнивают методами `Before`, `After`, `Equal`: `==` сравнивает ещё и внутреннее представление и пояс, поэтому равные моменты могут оказаться «не равны». `t.Add(time.Hour)` сдвигает момент, `t2.Sub(t1)` даёт длительность.
Нулевое значение — 1 января 1 года; проверяют его через `t.IsZero()`.

**Термины**
- **`time.Time`** — момент времени

#### GO-11.3.2 time.Duration
**Вопросы**
- [ ] Что такое `time.Duration` и почему это свой тип, а не просто `int64`? · `go time.Duration int64 nanoseconds`
- [ ] В каких единицах хранится длительность? · `time.Duration nanoseconds`
- [ ] Как записать 1,5 секунды и как перевести длительность в секунды (`Seconds()`)? · `go duration seconds float`
- [ ] Почему `fmt.Println(1500 * time.Millisecond)` печатает `1.5s`? · `go print duration format`
- [ ] Как разобрать строку `"2m30s"` (`time.ParseDuration`)? · `go time.ParseDuration`

**Гуглить:** `golang time.Duration` · `go duration constants`

**Должен знать**
`time.Duration` — свой тип на основе `int64`: число наносекунд. Константы `time.Second`, `time.Millisecond` и другие — это длительности, поэтому `90 * time.Second` читается естественно. У типа есть методы: `Seconds()`, `Minutes()`, `String()`.
Свой тип нужен, чтобы компилятор не дал перепутать «длительность» с обычным числом и чтобы у неё были свои методы. Печатается красиво (`1.5s`) потому, что у типа есть метод, превращающий его в строку.

**Термины**
- **`time.Duration`** — длительность в наносекундах, свой тип на основе `int64`

#### GO-11.3.3 Длительность, умноженная на число
**Вопросы**
- [ ] Почему `time.Sleep(n * time.Second)` не компилируется, если `n` — `int`? · `mismatched types int and time.Duration`
- [ ] Как исправить: `time.Duration(n) * time.Second`? · `go convert int to duration`
- [ ] Почему `2 * time.Second` при этом компилируется? · `untyped constant duration multiplication`
- [ ] Почему `time.Duration(n)` без умножения — это `n` наносекунд, а не секунд? · `time.Duration(5) nanoseconds bug`

**Гуглить:** `golang multiply duration by int` · `time.Duration conversion`

**Должен знать**
`n * time.Second` при `n int` — умножение `int` на `time.Duration`, разные типы, ошибка компиляции. Правильно: `time.Duration(n) * time.Second`. `2 * time.Second` компилируется, потому что `2` — нетипизированная константа и подстраивается под `Duration`.
Ловушка: `time.Sleep(time.Duration(5))` — это 5 наносекунд, а не секунд.

**Термины**
- **преобразование в `Duration`** — `time.Duration(n)`, число наносекунд

#### GO-11.3.4 Измерение прошедшего времени: time.Since
**Вопросы**
- [ ] Как измерить, сколько времени заняла функция? · `golang measure execution time time.Since`
- [ ] Почему `start := time.Now(); …; time.Since(start)` не ломается, если системные часы перевели? · `go monotonic clock`
- [ ] Как красиво замерить функцию через `defer` (и почему аргумент нужно обернуть)? · `go defer time.Since trick`
- [ ] Почему для оценки скорости кода одного замера мало? · `benchmark vs single measurement`

**Гуглить:** `go time.Since` · `go monotonic clock time`

**Должен знать**
`start := time.Now()` перед работой и `elapsed := time.Since(start)` после — стандартный замер. `time.Now()` хранит ещё и показание монотонных часов, которые не идут назад при переводе системного времени, поэтому разница всегда корректна.
С `defer` замер пишут так: `defer func() { log(time.Since(start)) }()` — иначе аргумент посчитается сразу. Для честной оценки скорости кода один замер не годится — для этого есть отдельный инструмент.

**Термины**
- **`time.Since`** — сколько прошло с момента `start`
- **монотонные часы** — часы, которые только идут вперёд

**Граница:** монотонные часы — одной фразой.

#### GO-11.3.5 Форматирование времени по образцу
**Вопросы**
- [ ] Как время форматируется в Go и что такое «образцовая» дата? · `go time format reference time`
- [ ] Что значит `"2006-01-02 15:04:05"` и почему именно эти числа (1, 2, 3, 4, 5, 6)? · `go 2006-01-02 15:04:05 why`
- [ ] Как разобрать строку с датой (`time.Parse`)? · `golang time.Parse example`
- [ ] Что такое `time.RFC3339` и почему для обмена данными берут его? · `go time RFC3339`
- [ ] Почему время в базе и между сервисами хранят и передают в UTC? · `store time in utc why`

**Гуглить:** `golang time format layout` · `go time.Parse` · `rfc3339`

**Должен знать**
Вместо `%Y-%m-%d` Go использует образцовую дату: «Mon Jan 2 15:04:05 MST 2006» — месяц 1, день 2, час 3 (15), минута 4, секунда 5, год 6. Формат пишут, как выглядела бы эта дата: `t.Format("2006-01-02 15:04")`. `time.Parse(layout, s)` разбирает строку по такому же образцу.
Для обмена данными берут `time.RFC3339`. Храни и передавай время в UTC, а в местное время переводи только при показе человеку.

**Термины**
- **образцовая дата** — 2006-01-02 15:04:05, по ней пишут форматы времени
- **UTC** — всемирное время без часовых поясов

**Граница:** часовые пояса — одной фразой, храним и передаём в UTC.

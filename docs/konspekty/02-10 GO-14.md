## GO-14. Дженерики

### GO-14.1 Параметры типа

#### GO-14.1.1 Дженерики: зачем они
**Вопросы**
- [ ] Какую проблему решают дженерики и как её решали до Go 1.18? · `why generics in go`
- [ ] Почему функцию `Max` для `int` и для `float64` до Go 1.18 писали дважды? · `go before generics duplicate code`
- [ ] Чем плох вариант с `any` и утверждением типа? · `interface{} vs generics type safety`
- [ ] Какими средствами в Go пишут код «для многих типов сразу» (интерфейсы, `any`, дженерики)? · `generic programming go options`
- [ ] Чем это похоже на `TypeVar` и аннотации в Python и чем отличается (проверка компилятором)? · `python typevar generics vs go`

**Гуглить:** `go generics tutorial` · `go blog intro generics` · `python typing TypeVar`

**Должен знать**
Дженерики позволяют написать функцию или тип один раз для многих типов, сохранив проверку типов компилятором. До Go 1.18 было два плохих пути: копировать код под каждый тип или принимать `any` и потом доставать тип обратно — с риском паники и без подсказок компилятора.
Мост из Python: похоже на `TypeVar` в аннотациях, но в Go это не подсказка, а правило: неверный тип просто не скомпилируется.

**Термины**
- **дженерики** *(новое)* — функции и типы с типом в роли параметра

#### GO-14.1.2 Параметр типа
**Вопросы**
- [ ] Что такое параметр типа и где он записывается (`func Max[T …](a, b T) T`)? · `go type parameters syntax`
- [ ] Как вызвать такую функцию с явным типом: `Max[int](1, 2)`? · `explicit type argument go`
- [ ] Можно ли у функции несколько параметров типа (`[K comparable, V any]`)? · `multiple type parameters go`
- [ ] Чем параметр типа отличается от обычного параметра? · `type parameter vs value parameter`

**Гуглить:** `go type parameters` · `go generics syntax square brackets`

**Должен знать**
Параметр типа — имя типа, которое функция получает при вызове, как обычный параметр получает значение. Записывается в квадратных скобках перед обычными параметрами: `func Max[T cmp.Ordered](a, b T) T`. При вызове подставляется конкретный тип — аргумент типа: `Max[int](1, 2)`.
Параметров типа может быть несколько: `func Keys[K comparable, V any](m map[K]V) []K`.

**Термины**
- **параметр типа** *(новое)* — тип, который функция получает как параметр
- **аргумент типа** — конкретный тип, подставленный при вызове

#### GO-14.1.3 Вывод аргументов типа
**Вопросы**
- [ ] Почему обычно можно писать `Max(1, 2)` без `[int]`? · `go type inference generics`
- [ ] Когда компилятор не может вывести тип и его нужно указать явно? · `cannot infer T`
- [ ] Какой тип выведется для `Max(1, 2.5)`? · `generic inference untyped constants`

**Гуглить:** `go type argument inference` · `go cannot infer T`

**Должен знать**
Компилятор выводит аргумент типа из обычных аргументов: в `Max(1, 2)` оба `int`, значит `T = int`. Явно тип указывают, когда выводить не из чего — например, параметр типа есть только у результата: `Zero[int]()`.
С нетипизированными константами компилятор выбирает подходящий общий тип: `Max(1, 2.5)` даст `float64`.

**Термины**
- **вывод аргументов типа** — компилятор сам определяет `T` по аргументам

#### GO-14.1.4 Ограничение типа
**Вопросы**
- [ ] Что такое ограничение типа? · `go type constraints`
- [ ] Почему без ограничения нельзя написать `a < b` для `T`? · `invalid operation operator < not defined on T`
- [ ] Почему ограничение — это интерфейс? · `constraint is interface go`
- [ ] Как требовать в ограничении метод (`T fmt.Stringer`)? · `generic constraint with method`

**Гуглить:** `go generics constraints` · `go constraint interface`

**Должен знать**
Ограничение типа говорит, какие типы можно подставить в параметр и что с ними можно делать в теле функции. `T` без ограничений ничего не умеет — даже `<`. Ограничение записывается интерфейсом: он может требовать методы (`T fmt.Stringer` — у типа есть `String()`) или перечислять разрешённые типы.
Компилятор проверяет тело функции против ограничения, а вызов — против аргумента типа.

**Термины**
- **ограничение типа** *(новое)* — интерфейс, задающий допустимые типы для параметра типа

#### GO-14.1.5 Ограничения any и comparable
**Вопросы**
- [ ] Чем ограничение `any` отличается от `comparable`? · `go any vs comparable constraint`
- [ ] Что можно делать со значением типа `T any`? · `what can you do with T any`
- [ ] Почему ключ map в функции с параметром типа требует `comparable`? · `generic map key comparable`
- [ ] Напиши `Contains[T comparable](s []T, x T) bool`. · `go generic contains function`

**Гуглить:** `go comparable constraint` · `go any constraint`

**Должен знать**
`any` — любой тип: такие значения можно хранить, копировать, передавать, но не сравнивать и не складывать. `comparable` — типы, значения которых сравниваются через `==`: нужно для поиска в слайсе и для ключей map.
Важное отличие от `any` как типа переменной: `T any` — это конкретный тип, известный при каждом вызове, а не «коробка с чем угодно».

**Термины**
- **`comparable`** — ограничение «значения сравнимы через `==`»

#### GO-14.1.6 Наборы типов и тильда ~
**Вопросы**
- [ ] Как перечислить разрешённые типы в ограничении: `interface { int | float64 }`? · `go union constraint`
- [ ] Что значит `~int` в ограничении? · `go tilde constraint`
- [ ] Почему без `~` свой тип `type Celsius float64` не подойдёт под `int | float64`? · `named type tilde constraint`
- [ ] Можно ли использовать такое ограничение как обычный тип переменной? · `cannot use interface with type set as type`

**Гуглить:** `go type sets` · `go tilde underlying type constraint`

**Должен знать**
Ограничение может перечислять типы: `interface { int | int64 | float64 }` — набор типов. Тогда в теле разрешены операции, общие для всех них: `+`, `<`.
`~float64` значит «любой тип, у которого базовый тип `float64»` — тогда подходит и `Celsius`. Без тильды подходит только сам `float64`. Интерфейсы с набором типов годятся только как ограничения, переменную такого типа объявить нельзя.

**Термины**
- **набор типов** *(новое)* — перечень типов, допустимых ограничением
- **`~T`** — все типы с базовым типом `T`

#### GO-14.1.7 Пакет cmp и cmp.Ordered
**Вопросы**
- [ ] Что такое `cmp.Ordered` и какие типы в него входят? · `go cmp.Ordered`
- [ ] Напиши `Max[T cmp.Ordered]`. · `go generic max cmp.Ordered`
- [ ] Чем полезны `cmp.Compare`, `cmp.Less` и `min`/`max` (встроенные с Go 1.21)? · `go 1.21 min max builtin`
- [ ] Почему `golang.org/x/exp/constraints` больше не нужен? · `x/exp/constraints vs cmp`

**Гуглить:** `go cmp package` · `go 1.21 min max`

**Должен знать**
`cmp.Ordered` — готовое ограничение: все типы, которые сравниваются через `<` (целые, дробные, строки, с тильдой). С ним `Max` пишется одной строкой. В пакете `cmp` есть и `Compare`, и `Less`, а с Go 1.21 `min` и `max` вообще встроены в язык.
Раньше похожие ограничения брали из экспериментального пакета; теперь хватает стандартной библиотеки.

**Термины**
- **`cmp.Ordered`** — ограничение «значения упорядочиваются через `<`»

### GO-14.2 Обобщённые типы

#### GO-14.2.1 Обобщённый тип
**Вопросы**
- [ ] Как написать обобщённый стек `type Stack[T any] struct { items []T }`? · `go generic stack`
- [ ] Как создать значение такого типа (`Stack[int]{}`)? · `instantiate generic type go`
- [ ] Почему `Stack[int]` и `Stack[string]` — разные типы? · `generic type instantiation distinct types`
- [ ] Как вернуть «пустое» значение `T` из `Pop`, если стек пуст (`var zero T`)? · `go generic zero value`

**Гуглить:** `go generic types` · `go generic data structures`

**Должен знать**
У типа тоже бывают параметры: `type Stack[T any] struct { items []T }`. Чтобы им пользоваться, подставляют тип: `var s Stack[int]`. `Stack[int]` и `Stack[string]` — разные типы.
Нулевое значение «какого-то» `T` получают так: `var zero T`. Это нужно, например, чтобы вернуть что-то из `Pop` пустого стека вместе с признаком `ok`.

**Термины**
- **обобщённый тип** *(новое)* — тип с параметрами типа

#### GO-14.2.2 Методы обобщённого типа
**Вопросы**
- [ ] Как объявить метод у `Stack[T]`: `func (s *Stack[T]) Push(x T)`? · `go generic type methods`
- [ ] Почему до Go 1.27 у метода не могло быть своих параметров типа? · `go methods cannot have type parameters`
- [ ] Что появилось у методов в Go 1.27? · `go 1.27 generic methods`
- [ ] Как раньше обходились без этого (обычная функция вместо метода)? · `generic function instead of method`

**Гуглить:** `go generic methods` · `go 1.27 release notes generic methods`

**Должен знать**
Метод обобщённого типа повторяет параметры типа в получателе: `func (s *Stack[T]) Push(x T)`. Ограничения второй раз не пишут.
Долгое время у метода не могло быть собственных параметров типа — только параметры его типа, и такие задачи решали обычными функциями. С Go 1.27 метод может объявить свои параметры типа.

**Термины**
- **метод обобщённого типа** — метод, получатель которого записан с параметрами типа

#### GO-14.2.3 Дженерик или интерфейс
**Вопросы**
- [ ] Когда лучше дженерик, а когда интерфейс? · `generics vs interfaces when to use`
- [ ] Почему для «сделай что-то с поведением» (вызвать метод) обычно хватает интерфейса? · `use interfaces for behavior`
- [ ] Почему для структур данных (стек, очередь) и алгоритмов над любыми данными лучше дженерик? · `generics for containers algorithms`
- [ ] Почему не стоит переписывать на дженерики всё подряд? · `go generics overuse`

**Гуглить:** `when to use generics go blog` · `generics vs interfaces golang`

**Должен знать**
Интерфейс — когда важно поведение: «умеет записывать», «умеет считать площадь». Код вызывает методы, а какой тип внутри — неважно. Дженерик — когда код одинаков для любых данных и важно сохранить их тип: структуры данных (стек, очередь), функции над слайсами и map (`slices.Index`, `maps.Keys`).
Правило из блога Go: если пишешь одно и то же для разных типов — дженерик; если вызываешь методы — интерфейс. Без явной нужды дженерики не добавляют.

**Термины**
- **дженерик против интерфейса** — общий алгоритм над данными против общего поведения

#### GO-14.2.4 Как компилятор превращает дженерик в код
**Вопросы**
- [ ] Создаёт ли компилятор отдельную копию функции для каждого типа? · `go generics implementation monomorphization`
- [ ] Что такое GC shape stenciling — одной фразой? · `go gc shape stenciling`
- [ ] Почему для всех указателей используется одна общая копия? · `generic pointer types same shape`
- [ ] Почему дженерик иногда медленнее, чем код, написанный под конкретный тип? · `go generics performance dictionary`

**Гуглить:** `go generics implementation gcshape` · `planetscale generics can make your go code slower`

**Должен знать**
Go не делает полную копию функции на каждый тип и не делает одну копию на все. Он делает копию на каждую «форму» типа с точки зрения памяти (GC shape): все указатели — одна форма, `int` — другая. Недостающие сведения о конкретном типе передаются в функцию скрытым «словарём».
Поэтому дженерик с указателями или интерфейсами иногда медленнее кода под конкретный тип: часть работы идёт через этот словарь.

**Термины**
- **GC shape stenciling** — по одной копии обобщённой функции на «форму» типа в памяти

**Граница:** GC shape stenciling — названием и одной фразой.

### GO-14.3 Итераторы

#### GO-14.3.1 for range по функции
**Вопросы**
- [ ] Как `for range` ходит по функции (Go 1.23)? · `go 1.23 range over func`
- [ ] Какой вид должна иметь функция, чтобы по ней можно было пройти? · `range over function signature`
- [ ] Что такое итератор и зачем он, если есть слайсы? · `iterator pattern go`
- [ ] Как пройти ключи map по порядку с `slices.Sorted(maps.Keys(m))`? · `maps.Keys iterator slices.Sorted`

**Гуглить:** `go 1.23 iterators` · `go blog range functions`

**Должен знать**
С Go 1.23 `for x := range f` работает и с функцией вида `func(body func(T) bool)` — она получает «тело цикла» как функцию. Такая функция — итератор: она сама перебирает значения и отдаёт их циклу по одному. Это позволяет обходить что угодно (дерево, строки файла, результат вычислений) без создания промежуточного слайса.
Так устроены новые функции стандартной библиотеки: `maps.Keys(m)` возвращает итератор, а `slices.Sorted` собирает его в отсортированный слайс.

**Термины**
- **итератор** *(новое)* — функция, которая по очереди отдаёт значения циклу

#### GO-14.3.2 Функция yield
**Вопросы**
- [ ] Что делает `yield` и что будет, если цикл прервали через `break`? · `go iterator yield break returns false`
- [ ] Почему итератор обязан перестать вызывать `yield`, если тот вернул `false`? · `yield returned false panic`
- [ ] Напиши итератор чисел от `a` до `b`. · `go write simple iterator`
- [ ] Можно ли из тела цикла сделать `return` и что произойдёт с итератором? · `return inside range over func`

**Гуглить:** `go iterator yield` · `range over func break`

**Должен знать**
`yield` — функция, которую цикл передаёт итератору: каждый вызов `yield(x)` выполняет тело цикла для `x`. Если в теле был `break` или `return`, `yield` вернёт `false`, и итератор должен сразу закончить работу — продолжать вызывать `yield` нельзя, будет паника.
Итератор чисел: `func Range(a, b int) iter.Seq[int] { return func(yield func(int) bool) { for i := a; i < b; i++ { if !yield(i) { return } } } }`.

**Термины**
- **yield** *(новое)* — функция-«отдать значение» внутри итератора

#### GO-14.3.3 iter.Seq и iter.Seq2
**Вопросы**
- [ ] Что такое `iter.Seq[V]` и `iter.Seq2[K, V]`? · `go iter.Seq iter.Seq2`
- [ ] Когда нужен `Seq2` (пары «номер — значение», «ключ — значение»)? · `iter.Seq2 key value`
- [ ] Чем итератор Go похож на генератор Python с `yield` и чем отличается (кто управляет циклом)? · `python generator vs go iterator`
- [ ] Что такое `iter.Pull` и когда нужен «вытягивающий» итератор — одной фразой? · `go iter.Pull`

**Гуглить:** `go iter package` · `python generators yield`

**Должен знать**
`iter.Seq[V]` — готовое имя типа итератора по одному значению, `iter.Seq2[K, V]` — по паре (как `range` по map). Их возвращают функции стандартной библиотеки, и ими принято описывать свои итераторы.
Мост из Python: похоже на генератор с `yield`, но наоборот по управлению: в Python цикл «вытягивает» значения из генератора, а в Go итератор сам «толкает» их в тело цикла. Для вытягивания есть `iter.Pull`.

**Термины**
- **`iter.Seq` / `iter.Seq2`** — стандартные типы итераторов по значению и по паре

**Граница:** `iter.Pull` — одной фразой.

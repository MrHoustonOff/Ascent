## GO-3. Условия, циклы, области видимости

### GO-3.1 Условия

#### GO-3.1.1 if и else
**Вопросы**
- [ ] Как записывается `if`/`else if`/`else` в Go и чем запись отличается от Python? · `golang if else`
- [ ] Почему фигурные скобки обязательны даже для одной строки, а круглые вокруг условия не нужны? · `go if braces required`
- [ ] Почему `else` должен стоять на той же строке, что и закрывающая `}`? · `go else must be on same line as brace`
- [ ] Что такое «ранний возврат» и почему в Go его предпочитают длинным `else`? · `go early return avoid else`

**Гуглить:** `golang if statement` · `go happy path left aligned`

**Должен знать**
`if условие { … } else if … { … } else { … }`: условие без скобок, тело — всегда в фигурных скобках, `else` — на одной строке с `}`, иначе компилятор вставит лишнюю точку с запятой. Условие обязано быть `bool`.
Стиль Go — ранний возврат: обработал ошибку или особый случай — сразу `return`, а основной путь кода идёт без вложенности, у левого края.

**Термины**
- **ранний возврат** — выход из функции сразу после особого случая, без `else`

**Граница:** правила автоматической расстановки точек с запятой — достаточно примера с `else`.

#### GO-3.1.2 if с инициализацией
**Вопросы**
- [ ] Как записать условие с коротким объявлением переменной прямо в `if`? · `go if with short statement`
- [ ] Где видна переменная, объявленная в `if v := f(); v > 0`: в `else`? после `if`? · `go if init statement scope else`
- [ ] Почему `if err := do(); err != nil { … }` — частая форма в Go? · `go if err := idiom`
- [ ] Когда лучше объявить переменную до `if`, а не внутри? · `go if init vs declare before`

**Гуглить:** `golang if with initialization` · `go if statement scope`

**Должен знать**
`if v := f(); v > 0 { … }` — сначала выполняется короткое объявление, потом проверяется условие. Переменная `v` видна внутри `if` и во всех `else`, но не после всего оператора.
Так удобно проверять ошибку, которая дальше не нужна: `if err := save(); err != nil { return err }`. Если значение нужно ниже, его объявляют перед `if`.

**Термины**
- **инициализация в `if`** — короткое объявление перед условием, видно только внутри `if`/`else`

#### GO-3.1.3 switch по значению
**Вопросы**
- [ ] Чем `switch` в Go отличается от цепочки `if/else` и от `match` в Python? · `go switch vs python match`
- [ ] Нужен ли `break` в конце `case`? · `go switch no break needed`
- [ ] Можно ли в одном `case` перечислить несколько значений через запятую? · `go switch multiple values case`
- [ ] Что делает `default` и обязательно ли он нужен? · `go switch default`
- [ ] Может ли `switch` иметь инициализацию, как `if`? · `go switch with init statement`

**Гуглить:** `golang switch statement` · `go switch multiple cases`

**Должен знать**
`switch x { case 1, 2: …; case 3: …; default: … }` сравнивает `x` со значениями сверху вниз и выполняет первый подходящий `case`. После него выполнение выходит из `switch` само — `break` не нужен, «проваливания» в следующий `case` по умолчанию нет.
В одном `case` можно перечислить несколько значений. `default` — если ничего не подошло, необязателен.

**Термины**
- **`case`** — вариант в `switch`
- **`default`** — ветка, если ни один `case` не подошёл

**Граница:** `match` из Python с разбором формы значения — аналога в Go нет, сравнивать не нужно.

#### GO-3.1.4 switch без выражения
**Вопросы**
- [ ] Как написать `switch` без выражения и когда он удобнее `if`? · `go switch true`
- [ ] Как проверяются условия: по порядку, до первого истинного? · `go tagless switch order`
- [ ] Можно ли в одном `case` проверить несколько условий? · `go switch case multiple conditions`
- [ ] Перепиши цепочку из четырёх `if/else if` через `switch`. · `go replace if else chain with switch`

**Гуглить:** `golang switch without condition` · `go expressionless switch`

**Должен знать**
`switch { case x < 0: …; case x == 0: …; default: … }` — каждый `case` содержит своё условие, выполняется первый истинный. Это то же, что `switch true`.
Такая форма читается лучше длинной цепочки `if/else if`, когда веток три и больше. Несколько условий в одном `case` объединяют через `||` или перечисляют через запятую.

**Термины**
- **`switch` без выражения** — каждый `case` проверяет своё условие

#### GO-3.1.5 fallthrough
**Вопросы**
- [ ] Что делает `fallthrough`? · `go fallthrough`
- [ ] Проверяет ли `fallthrough` условие следующего `case`? · `go fallthrough does not check condition`
- [ ] Где стоит `fallthrough` и можно ли его поставить в последнем `case`? · `go fallthrough last case error`
- [ ] Почему `fallthrough` почти не используют? · `go fallthrough rarely used`

**Гуглить:** `golang fallthrough keyword` · `fallthrough example go`

**Должен знать**
`fallthrough` в конце `case` переходит в тело следующего `case`, вообще не проверяя его условие. Это явная просьба «провалиться», которая в C происходит по умолчанию.
Используют его редко: почти всегда понятнее перечислить значения через запятую в одном `case`. Знать нужно для собеса и чтобы не удивляться.

**Термины**
- **fallthrough** *(новое)* — переход к телу следующего `case` без проверки его условия

### GO-3.2 Циклы

#### GO-3.2.1 Цикл for с тремя частями
**Вопросы**
- [ ] Из каких трёх частей состоит `for i := 0; i < 10; i++`? Какая часть когда выполняется? · `go for loop three components`
- [ ] Где видна переменная `i`, объявленная в `for`? · `go for loop variable scope`
- [ ] Почему в Go один цикл `for`, а в Python есть `for` и `while`? · `go only for loop why`
- [ ] Как пройти числа от 10 до 0 с шагом 2? · `go for loop decrement step`

**Гуглить:** `golang for loop` · `go tour for`

**Должен знать**
`for инициализация; условие; шаг { … }`: инициализация выполняется один раз, условие — перед каждой итерацией, шаг — после каждой. Переменная из инициализации видна только внутри цикла.
В Go единственное ключевое слово цикла — `for`; разные формы записи заменяют и `for`, и `while`.

**Термины**
- **итерация** — одно выполнение тела цикла

**Позже:** что изменилось с переменной цикла в Go 1.22 — GO-4.4.4.

#### GO-3.2.2 Цикл for с одним условием
**Вопросы**
- [ ] Как записать на Go аналог `while` из Python? · `go while loop equivalent`
- [ ] Перепиши `while n > 0: n //= 10` на Go. · `go for condition only`
- [ ] Чем `for n > 0 { }` отличается от `for ; n > 0; { }`? · `go for loop omit init post`

**Гуглить:** `golang while loop` · `go for as while`

**Должен знать**
`for условие { … }` — это `while` из Python: цикл крутится, пока условие истинно. Части инициализации и шага можно просто не писать вместе с точками с запятой.

**Термины**
- **цикл с условием** — `for` только с условием, аналог `while`

#### GO-3.2.3 Бесконечный цикл и break
**Вопросы**
- [ ] Как записать бесконечный цикл в Go? · `go infinite loop for {}`
- [ ] Как выйти из него через `break`? · `go break out of loop`
- [ ] Когда бесконечный цикл с `break` понятнее цикла с условием? · `loop with break in middle`
- [ ] Что будет, если в бесконечном цикле забыть `break` или `return`? · `infinite loop cpu 100`

**Гуглить:** `golang infinite loop` · `go break statement`

**Должен знать**
`for { … }` крутится вечно, пока его не прервёт `break` или `return`. Это удобно, когда условие выхода проверяется в середине тела, а не в начале.
Забытый выход — программа зависает и съедает целое ядро процессора.

**Термины**
- **`break`** — немедленный выход из цикла

#### GO-3.2.4 continue
**Вопросы**
- [ ] Что делает `continue` в каждой из форм `for`? · `go continue statement`
- [ ] Выполнится ли шаг `i++` после `continue` в цикле с тремя частями? · `go continue post statement executed`
- [ ] Перепиши вложенный `if` внутри цикла через `continue`. · `continue reduce nesting`

**Гуглить:** `golang continue` · `go loop skip iteration`

**Должен знать**
`continue` прерывает текущую итерацию и переходит к следующей. В цикле с тремя частями перед следующей проверкой условия выполнится шаг — `i++` не теряется.
Как и ранний возврат, `continue` помогает не городить вложенность: «неинтересный» элемент отсеяли в начале тела.

**Термины**
- **`continue`** — переход к следующей итерации цикла

#### GO-3.2.5 for range по числу (Go 1.22)
**Вопросы**
- [ ] Как записать `for i := range 10` и какие значения получит `i`? · `go 1.22 range over int`
- [ ] Чем это похоже на `for i in range(10)` в Python и чем отличается (нет шага и начала)? · `go range int vs python range`
- [ ] Как пройти числа от 0 до 9 двумя способами? · `go loop 0 to 9`
- [ ] Почему эта форма появилась только в Go 1.22 и что будет на более старой версии? · `go 1.22 release notes range int`

**Гуглить:** `go 1.22 range over integer` · `golang for range int`

**Должен знать**
С Go 1.22 можно писать `for i := range 10` — `i` пройдёт от 0 до 9. Это короче цикла с тремя частями, но умеет только «от нуля с шагом 1»; для другого начала или шага пиши обычный `for`. Если номер не нужен, можно `for range 10`.
Версию языка задаёт строка `go` в `go.mod` — со старой версией эта форма не скомпилируется.

**Термины**
- **`range` по числу** — цикл по числам от 0 до n−1

**Позже:** `range` по строке — GO-8.1.4.

#### GO-3.2.6 Метки для break и continue
**Вопросы**
- [ ] Как выйти из внешнего цикла, находясь во вложенном? · `go break outer loop label`
- [ ] Как записать метку и `break Метка` / `continue Метка`? · `go labeled break continue`
- [ ] Чем `continue Outer` отличается от `break` во вложенном цикле? · `go continue label`
- [ ] Что такое `goto` и почему его почти не используют? · `go goto statement`
- [ ] Как решить ту же задачу без метки — вынести вложенный цикл в функцию с `return`? · `refactor nested loops function return`

**Гуглить:** `golang labels break continue` · `go goto`

**Должен знать**
`break` и `continue` действуют на ближайший цикл. Чтобы выйти из внешнего, его помечают: `Outer: for … { for … { break Outer } }`. `continue Outer` переходит к следующей итерации внешнего цикла.
Часто понятнее вынести вложенные циклы в функцию и выйти через `return`. `goto` в Go есть, но в обычном коде его не пишут.

**Термины**
- **метка** *(новое)* — имя перед циклом, на которое ссылаются `break` и `continue`
- **`goto`** — переход к метке; почти не используется

**Граница:** `goto` — одной фразой.

#### GO-3.2.7 break внутри switch в цикле
**Вопросы**
- [ ] Что сделает `break` внутри `switch`, который стоит в цикле? · `go break inside switch in for loop`
- [ ] Как выйти именно из цикла: метка или флаг? · `go break out of for from switch`
- [ ] Почему это частый баг при переходе с Python? · `go switch break gotcha`
- [ ] А `continue` внутри `switch` — к чему относится? · `go continue inside switch`

**Гуглить:** `golang break switch for loop` · `go labeled break switch`

**Должен знать**
`break` внутри `switch` выходит из `switch`, а не из цикла вокруг него — цикл продолжит крутиться. Чтобы выйти из цикла, ставят метку на `for` и пишут `break Loop`, или выходят через `return`.
`continue` к `switch` не относится и действует на цикл, как и ожидаешь.

**Термины**
- **`break` в `switch`** — выходит из `switch`, а не из цикла

### GO-3.3 Области видимости

#### GO-3.3.1 Блоки и область видимости
**Вопросы**
- [ ] Что такое область видимости и что создаёт новую область? · `go scope blocks`
- [ ] Почему переменная, объявленная внутри `if` или `for`, не видна снаружи? · `go variable not visible outside block`
- [ ] Что такое фигурные скобки без оператора внутри функции и зачем они? · `go bare block`
- [ ] Чем это отличается от Python, где переменная из тела `if` видна после него? · `python if block scope leak`
- [ ] Видна ли переменная до строки, на которой её объявили? · `go use before declaration`

**Гуглить:** `golang variable scope` · `go blocks scope spec`

**Должен знать**
Область видимости — участок кода, где имя доступно. В Go её создаёт каждый блок в фигурных скобках: тело функции, `if`, `for`, `case` и даже просто `{ … }` внутри функции. Переменная видна от места объявления до конца своего блока.
Мост из Python: там блок `if` или `for` не создаёт новой области, и переменная «вытекает» наружу. В Go так не бывает.

**Термины**
- **область видимости** *(новое)* — участок кода, где доступно имя
- **блок** — код в фигурных скобках

#### GO-3.3.2 Затенение переменных
**Вопросы**
- [ ] Что такое затенение? Покажи, как `:=` внутри `if` создаёт новую переменную вместо изменения старой. · `go variable shadowing`
- [ ] Почему баг с `err`, объявленным через `:=` во внутреннем блоке, так частый? · `go shadowed err bug`
- [ ] Почему компилятор не считает затенение ошибкой? · `go shadowing allowed why`
- [ ] Как найти затенение инструментами (`go vet -vettool`, `shadow`, линтеры)? · `go vet shadow analyzer`
- [ ] Как чинить: заменить `:=` на `=` или объявить переменную заранее? · `fix shadowed variable go`

**Гуглить:** `golang shadowing` · `go shadowed err` · `golangci-lint shadow`

**Должен знать**
Затенение — когда во внутреннем блоке объявлена переменная с тем же именем, что и снаружи. Внутри блока видна новая, внешняя скрыта. Типичный баг: `x, err := f()` внутри `if` создаёт новый `err`, а внешний остаётся `nil`, и ошибка теряется.
Компилятор это разрешает, поэтому смотри на `:=` во вложенных блоках и используй `=`, если хочешь изменить существующую переменную. Линтеры умеют находить затенение.

**Термины**
- **затенение** *(новое)* — внутреннее имя скрывает внешнее с тем же именем

**Граница:** настройка линтеров — позже, в ИНФРА-4.2.3.

#### GO-3.3.3 Переменные уровня пакета
**Вопросы**
- [ ] Как объявить переменную вне функций и где она видна? · `go package level variable`
- [ ] Почему вне функций нельзя использовать `:=`? · `go non-declaration statement outside function body`
- [ ] Чем опасны переменные уровня пакета (кто угодно меняет, сложно тестировать)? · `why avoid global variables go`
- [ ] Когда они уместны (константы-настройки, заранее подготовленные значения)? · `go global variables acceptable use`
- [ ] Чем это похоже на глобальные переменные модуля в Python? · `python module global variable`

**Гуглить:** `golang global variables` · `go package variables bad practice`

**Должен знать**
Переменная, объявленная через `var` вне функций, живёт всё время работы программы и видна во всём пакете. `:=` там нельзя — только `var`.
Опасность в том, что её может изменить любая функция пакета, поэтому поведение кода зависит от скрытого состояния, а тесты мешают друг другу. Хороший код передаёт нужные значения явно, а на уровне пакета держит в основном то, что не меняется.

**Термины**
- **переменная уровня пакета** — переменная вне функций, видна во всём пакете

## GO-8. Строки изнутри

### GO-8.1 Строка как байты

#### GO-8.1.1 Заголовок строки: указатель и длина
**Вопросы**
- [ ] Из чего состоит заголовок строки и сколько он весит? · `go string header pointer length`
- [ ] Чем заголовок строки отличается от заголовка слайса (нет ёмкости)? · `go string vs slice header`
- [ ] Что копируется при `t := s` и при передаче строки в функцию? · `go string assignment copies header`
- [ ] Почему передать в функцию строку на мегабайт дёшево? · `passing large string cost go`
- [ ] Какое нулевое значение у строки и чем оно отличается от nil? · `go string zero value cannot be nil`

**Гуглить:** `go string internals` · `go blog strings bytes runes characters`

**Должен знать**
Строка в Go — заголовок из двух полей: указатель на байты и длина (16 байт на 64-битной системе). Ёмкости нет: строка никогда не растёт на месте. Присваивание и передача в функцию копируют только заголовок, поэтому даже огромная строка передаётся дёшево.
Нулевое значение строки — `""`; nil строкой быть не может.

**Термины**
- **заголовок строки** — указатель на байты и длина

#### GO-8.1.2 Неизменяемость строк
**Вопросы**
- [ ] Почему строку нельзя изменить по одному символу (`s[0] = 'H'` не компилируется)? · `go cannot assign to s[0] string`
- [ ] Что тогда делает `s += "!"`: меняет строку или создаёт новую? · `go string concatenation creates new string`
- [ ] Почему неизменяемость позволяет безопасно делить байты между строками? · `immutable strings share memory`
- [ ] Как изменить один символ: через `[]byte` или `[]rune` и обратно? · `go modify character in string`
- [ ] Как устроена `str` в CPython и почему она тоже неизменяема? · `python str immutable why`

**Гуглить:** `golang strings immutable` · `python str immutability reasons`

**Должен знать**
Байты строки нельзя изменить: `s[0] = 'H'` — ошибка компиляции. Любая «модификация» создаёт новую строку, а старая остаётся как была. Благодаря этому строки могут безопасно делить одни и те же байты: две переменные смотрят в общую память, и ни одна не может испортить данные другой.
Чтобы поменять символ, строку переводят в изменяемый слайс, меняют и переводят обратно. Мост из Python: `str` там тоже неизменяема — по тем же причинам.

**Термины**
- **неизменяемость** *(новое)* — значение нельзя изменить после создания, только создать новое

#### GO-8.1.3 Обращение s[i] к строке
**Вопросы**
- [ ] Что вернёт `s[0]` для строки «привет» и почему это не буква? · `go string index returns byte`
- [ ] Какой тип у `s[0]` и как его напечатать (`%d`, `%x`, `%c`)? · `go s[i] type byte`
- [ ] Почему `s[0]` для «hello» даёт ровно `'h'`, а для «привет» — половину буквы? · `utf-8 cyrillic two bytes index`
- [ ] Чем это отличается от `s[0]` в Python? · `python string index code point`
- [ ] Почему найти N-й символ строки — это проход с начала, а не мгновенный доступ? · `utf-8 nth character linear time`

**Гуглить:** `golang string indexing byte` · `go string index utf8`

**Должен знать**
`s[i]` возвращает i-й байт строки (тип `byte`), а не символ. Для латиницы байт совпадает с буквой, но русская буква в UTF-8 занимает 2 байта, поэтому `"привет"[0]` — это 208, первая половина буквы «п».
Мост из Python: там `s[0]` — символ. В Go, чтобы получить N-й символ, приходится идти от начала строки, потому что символы разной длины.

**Термины**
- **байт строки** — `s[i]`, один байт UTF-8, тип `byte`

#### GO-8.1.4 for range по строке
**Вопросы**
- [ ] Что лежит в двух переменных цикла `for i, r := range s`? · `go range over string rune index`
- [ ] Почему номера `i` в цикле по «привет» идут 0, 2, 4…? · `range string byte offset`
- [ ] Какой тип у `r`? · `go range string rune type`
- [ ] Что будет, если в строке встретятся неправильные байты UTF-8? · `go range invalid utf-8 U+FFFD`
- [ ] Чем `for i := 0; i < len(s); i++` по строке отличается от `range`? · `go iterate string bytes vs runes`

**Гуглить:** `golang range string` · `go range string runes byte index`

**Должен знать**
`for i, r := range s` идёт по строке символами: `r` — руна (code point), а `i` — номер байта, с которого она начинается. Для «привет» номера будут 0, 2, 4, 6, 8, 10. Обычный цикл по `len(s)` идёт по байтам.
Если байты не складываются в правильный UTF-8, `range` выдаёт специальную руну `U+FFFD` («символ замены») и идёт дальше.

**Термины**
- **`range` по строке** — цикл по рунам с номером начального байта
- **`U+FFFD`** — символ замены для неправильных байтов UTF-8

#### GO-8.1.5 Количество символов против len
**Вопросы**
- [ ] Как посчитать количество символов в строке, а не байтов? · `go count runes in string`
- [ ] Что вернут `len("hello")`, `len("привет")` и `len("👋")`? · `go len unicode string`
- [ ] Чем `utf8.RuneCountInString(s)` отличается от `len([]rune(s))` по цене? · `RuneCountInString vs len []rune`
- [ ] Почему «количество символов» может не совпадать с тем, что видит человек (эмодзи из нескольких code point)? · `grapheme cluster emoji length`
- [ ] Какую длину проверять для ограничения «имя не длиннее 50 символов»? · `validate string length characters go`

**Гуглить:** `golang string length characters` · `utf8.RuneCountInString`

**Должен знать**
`len(s)` — число байтов; `utf8.RuneCountInString(s)` — число рун. «hello» — 5 и 5, «привет» — 12 и 6, «👋» — 4 и 1. `len([]rune(s))` даёт тот же ответ, но создаёт лишний слайс.
Руны — ещё не «буквы на экране»: некоторые эмодзи и буквы с ударением собираются из нескольких рун. Для обычных проверок длины руны подходят; точный подсчёт видимых символов требует отдельной библиотеки.

**Термины**
- **количество рун** — число code point в строке

**Граница:** графемные кластеры — одной фразой.

#### GO-8.1.6 Нарезка строки
**Вопросы**
- [ ] Что будет при нарезке `s[0:1]` у строки на русском? · `go slice string cyrillic broken`
- [ ] Копирует ли нарезка строки байты? · `go substring shares memory`
- [ ] Как правильно взять первые N символов строки? · `go first n characters string runes`
- [ ] Как безопасно резать по номеру байта, полученному из `range` или `strings.Index`? · `go slice string at rune boundary`

**Гуглить:** `golang substring` · `go slice string unicode safe`

**Должен знать**
`s[a:b]` у строки работает как у слайса, но по байтам и без копирования: новая строка смотрит в те же байты. `s[0:1]` у «привет» — половина буквы, неправильный UTF-8.
Резать безопасно по номерам, которые точно стоят на границе символа: из `range` или из функций поиска. Чтобы взять первые N символов, проходят строку `range` до N-й руны или переводят в `[]rune`.

**Термины**
- **граница символа** — номер байта, с которого начинается руна

#### GO-8.1.7 Подстрока и память исходной строки
**Вопросы**
- [ ] Почему маленькая подстрока может удерживать в памяти огромную строку? · `go substring memory leak`
- [ ] Как отвязать подстроку от исходной (`strings.Clone`)? · `golang strings.Clone`
- [ ] Когда это реально важно (разбор огромного файла, долгоживущие кэши)? · `substring retention large file parsing`

**Гуглить:** `go substring keeps original alive` · `strings.Clone go 1.20`

**Должен знать**
Нарезка строки смотрит в те же байты, поэтому, пока жива подстрока, жива вся исходная строка — та же история, что с нарезкой слайса. Вырезал 10 символов из прочитанного файла на 100 МБ — держишь в памяти 100 МБ.
С Go 1.20 есть `strings.Clone`: он копирует подстроку в новую память, и исходная строка может освободиться.

**Термины**
- **удержание исходной строки** — подстрока не даёт освободить большую строку

### GO-8.2 Преобразования

#### GO-8.2.1 string и []byte
**Вопросы**
- [ ] Что происходит при преобразовании `string` в `[]byte` и обратно? · `go convert string to byte slice copy`
- [ ] Почему преобразование обязано копировать байты? · `why string to []byte copies`
- [ ] Где ты встретишь `[]byte` вместо строки (чтение файлов, сеть, разбор форматов)? · `go io uses byte slices`
- [ ] Какие функции пакета `bytes` повторяют пакет `strings`? · `go bytes package vs strings`

**Гуглить:** `golang string to byte slice` · `go bytes package`

**Должен знать**
`[]byte(s)` создаёт новый изменяемый слайс с копией байтов строки, `string(b)` — новую строку с копией байтов слайса. Копия обязательна: иначе изменение слайса испортило бы неизменяемую строку.
`[]byte` — основной тип для ввода-вывода: чтение файлов, сеть, разбор форматов. Для него есть пакет `bytes` с теми же функциями, что `strings`.

**Термины**
- **`[]byte`** — изменяемый слайс байтов; основной тип для ввода-вывода

#### GO-8.2.2 string и []rune
**Вопросы**
- [ ] Когда нужен `[]rune` вместо `[]byte`? · `go when to use []rune`
- [ ] Сколько памяти займёт `[]rune("привет")` по сравнению со строкой? · `[]rune memory 4 bytes per rune`
- [ ] Как развернуть строку с русскими буквами? · `go reverse string unicode`
- [ ] Как взять N-й символ через `[]rune`? · `go get nth character rune`

**Гуглить:** `golang []rune conversion` · `go reverse utf8 string`

**Должен знать**
`[]rune(s)` раскладывает строку на руны: каждый символ — отдельный элемент `int32`, и с ним можно работать по номеру — развернуть строку, поменять символ, взять N-й. `string(r)` собирает строку обратно.
Цена: копия данных, и каждая руна занимает 4 байта — «привет» вырастает с 12 байтов до 24. Поэтому `[]rune` берут, когда действительно нужна работа по символам.

**Термины**
- **`[]rune`** — слайс рун; позволяет работать со строкой посимвольно

#### GO-8.2.3 Цена преобразования
**Вопросы**
- [ ] Почему каждое такое преобразование стоит денег? · `string conversion allocation cost go`
- [ ] Как избежать лишних преобразований в цикле (работать сразу с `[]byte`)? · `avoid string byte conversion loop`
- [ ] Когда компилятор убирает копию сам (сравнение, ключ при поиске)? · `go compiler optimization string(bytes) no copy`
- [ ] Почему `unsafe`-трюки для «бесплатного» преобразования опасны? · `unsafe string bytes conversion danger`

**Гуглить:** `go string byte conversion performance` · `go zero copy string conversion`

**Должен знать**
Преобразование между строкой и слайсом — это выделение новой памяти и копирование всех байтов. Один раз — незаметно, в горячем цикле — заметно. Поэтому данные стараются держать в одном виде и не гонять туда-обратно.
В некоторых случаях компилятор сам понимает, что копия не нужна (например, временная строка только для сравнения). Обходить копирование через `unsafe` в обычном коде не стоит: изменение слайса сломает «неизменяемую» строку.

**Термины**
- **цена преобразования** — выделение памяти и копирование при переходе между `string` и `[]byte`

**Граница:** оптимизации компилятора, которые копию убирают, — одной фразой.

### GO-8.3 Сборка строк

#### GO-8.3.1 Склейка в цикле и её цена
**Вопросы**
- [ ] Почему склейка строк через `+` в цикле медленная? · `go string concatenation loop slow`
- [ ] Сколько байтов скопируется при склейке 1000 строк по 10 байтов через `+=`? · `quadratic string concatenation`
- [ ] Почему для двух-трёх строк `+` — нормально? · `when string + is fine`
- [ ] Замерь склейку 10 000 строк через `+=` с `time.Since` — сколько это занимает? · `go benchmark string concatenation`

**Гуглить:** `golang string concatenation performance` · `quadratic concatenation`

**Должен знать**
Строки неизменяемы, поэтому `s += x` каждый раз создаёт новую строку и копирует в неё все накопленные байты. В цикле из N шагов это примерно N²/2 копирований — время растёт квадратично.
Для двух-трёх строк `+` — нормальный и самый читаемый способ. Для сборки в цикле нужен инструмент, который копит байты без повторного копирования.

**Термины**
- **квадратичная склейка** — повторное копирование накопленного текста на каждом шаге

#### GO-8.3.2 strings.Builder
**Вопросы**
- [ ] Как работает `strings.Builder` и почему он быстрее? · `golang strings.Builder`
- [ ] Какие функции у него есть (`WriteString`, `WriteByte`, `WriteRune`, `String`, `Grow`)? · `strings.Builder methods`
- [ ] Почему `String()` не копирует данные? · `strings.Builder String no copy`
- [ ] Почему `Builder` нельзя копировать после начала записи? · `strings.Builder copy panic`
- [ ] Чем это похоже на `"".join(parts)` в Python? · `python join vs go builder`
- [ ] Когда удобнее `strings.Join`? · `go strings.Join`

**Гуглить:** `go strings.Builder example` · `python str join performance` · `strings.Join`

**Должен знать**
`strings.Builder` копит байты в растущем слайсе (как `append`, с запасом), а `String()` в конце отдаёт результат без лишней копии. Если итоговый размер известен, `Grow(n)` заранее выделит место. Скопировать заполненный `Builder` нельзя — он запаникует.
Если части уже лежат в слайсе, проще `strings.Join(parts, ", ")` — прямой аналог `", ".join(parts)` в Python.

**Термины**
- **strings.Builder** *(новое)* — накопитель для эффективной сборки строки по частям
- **`strings.Join`** — склеить слайс строк с разделителем

#### GO-8.3.4 Пакет unicode/utf8

- [ ] Как посчитать руны в строке без преобразования в `[]rune`? · `utf8.RuneCountInString`

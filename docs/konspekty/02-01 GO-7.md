## GO-7. Массивы и слайсы

### GO-7.1 Массив

#### GO-7.1.1 Массив
**Вопросы**
- [ ] Что такое массив в Go и как его объявить (`var a [5]int`, `[3]string{"a", "b", "c"}`)? · `golang arrays`
- [ ] Почему длину массива нельзя изменить после создания? · `go array fixed size`
- [ ] Что значит `[...]int{1, 2, 3}`? · `go array literal ellipsis`
- [ ] Чем массив в Go отличается от `list` в Python? · `python list vs go array`
- [ ] Почему массивы в Go используют редко, а знать их всё равно нужно? · `go arrays vs slices when use array`

**Гуглить:** `go tour arrays` · `golang array declaration` · `python list internals`

**Должен знать**
Массив — фиксированное количество значений одного типа, лежащих подряд: `[5]int` — ровно пять `int`, все сразу с нулевыми значениями. Длина задаётся при объявлении и не меняется; `[...]` просит компилятор посчитать её по литералу.
Мост из Python: `list` растёт, хранит что угодно и на деле похож на другой тип Go — его разберём в следующей теме. Сам массив в Go нужен редко, но на нём построено многое, что будет дальше.

**Термины**
- **массив** *(новое)* — фиксированное число значений одного типа подряд в памяти
- **элемент** — одно значение внутри массива

#### GO-7.1.2 Как массив лежит в памяти
**Вопросы**
- [ ] Как массив лежит в памяти и почему по номеру элемент находится мгновенно? · `array memory layout contiguous`
- [ ] Как вычислить адрес элемента `a[i]`, зная адрес начала и размер элемента? · `array element address formula`
- [ ] Сколько байтов занимает `[4]int64`? А `[4]int8`? · `go array size in bytes`
- [ ] Почему соседние элементы в памяти быстрее перебирать, чем разбросанные (кэш процессора — одной фразой)? · `cache locality arrays`

**Гуглить:** `array contiguous memory` · `array index address calculation`

**Должен знать**
Элементы массива лежат в памяти вплотную друг за другом. Поэтому адрес элемента вычисляется одной формулой: адрес начала + `i` × размер элемента — найти `a[1000]` так же быстро, как `a[0]`. Размер массива — длина × размер элемента: `[4]int64` занимает 32 байта.
Значения, лежащие рядом, процессор читает особенно быстро, поэтому перебор массива подряд — один из самых быстрых способов обработки данных.

**Термины**
- **непрерывная память** — элементы лежат подряд без промежутков
- **доступ по номеру** — получение элемента за одно и то же время, где бы он ни был

**Граница:** кэши процессора — одной фразой.

#### GO-7.1.3 Длина массива и его тип
**Вопросы**
- [ ] Почему `[3]int` и `[4]int` — разные типы? · `go array length part of type`
- [ ] Можно ли передать `[4]int` в функцию, которая ждёт `[3]int`? · `go cannot use [4]int as [3]int`
- [ ] Почему длина массива должна быть известна при компиляции? · `go array length must be constant`
- [ ] Как узнать длину массива (`len`)? · `go len array`

**Гуглить:** `golang array type includes length` · `go array length constant`

**Должен знать**
Длина входит в тип массива: `[3]int` и `[4]int` — разные, несовместимые типы. Поэтому функция, принимающая `[3]int`, не примет массив другой длины, а длину нельзя задать значением, вычисленным во время работы, — только константой.
Из-за этого массив неудобен для «списка неизвестной длины» — для этого в Go есть отдельный тип. `len(a)` у массива известен уже при компиляции.

**Термины**
- **длина массива** — число элементов; часть типа массива

#### GO-7.1.4 Обращение к элементу и выход за границы
**Вопросы**
- [ ] Что будет при обращении к элементу с номером, которого нет? · `go index out of range panic`
- [ ] Почему `a[5]` при длине 5 компилятор ловит сам, а `a[i]` — только во время работы? · `go constant index out of range compile error`
- [ ] Есть ли в Go отрицательные номера, как `a[-1]` в Python? · `go negative index`
- [ ] Почему проверка границ защищает от целого класса уязвимостей из C? · `bounds checking buffer overflow`
- [ ] Как правильно получить последний элемент? · `go last element len-1`

**Гуглить:** `golang index out of range` · `go bounds check`

**Должен знать**
Номера элементов — от 0 до `len(a)-1`. Если номер за пределами и он известен при компиляции, сборка не пройдёт; если вычислен во время работы — паника `index out of range`. Читать или писать за пределами массива Go не даёт никогда.
Отрицательных номеров, как в Python, нет: последний элемент — `a[len(a)-1]`.

**Термины**
- **проверка границ** — Go проверяет номер элемента при каждом обращении
- **выход за границы** — обращение к несуществующему элементу; вызывает панику

#### GO-7.1.5 Массив при присваивании и передаче в функцию
**Вопросы**
- [ ] Функция изменила элемент переданного массива. Что увидит вызывающий и почему? · `go array passed by value copy`
- [ ] Что будет в `a` после `b := a; b[0] = 99`? · `go array assignment copies`
- [ ] Сколько стоит передать в функцию `[1000000]int`? · `go large array copy cost`
- [ ] Как дать функции изменить массив вызывающего? · `go pointer to array parameter`
- [ ] Чем это отличается от передачи `list` в Python? · `python list mutable in function`

**Гуглить:** `golang arrays are values` · `go array copy semantics`

**Должен знать**
Массив в Go — обычное значение: присваивание и передача в функцию копируют все элементы. После `b := a` изменение `b` не трогает `a`, и функция меняет только свою копию. Для больших массивов это дорого — копируются все байты.
Если функции нужно менять массив вызывающего, передают указатель `*[N]T`, но на практике для этого есть более удобный тип. В Python передача `list` всегда даёт доступ к тому же объекту.

**Термины**
- **массив-значение** — массив копируется целиком при присваивании и передаче

#### GO-7.1.6 Сравнение массивов
**Вопросы**
- [ ] Можно ли сравнить два массива через `==`? · `go compare arrays ==`
- [ ] Когда массивы равны: тот же тип и все элементы равны? · `go array equality`
- [ ] Можно ли сравнить массивы разной длины? · `go compare arrays different length`
- [ ] Почему массив можно использовать там, где нужно сравниваемое значение (ключ)? · `go array as map key`

**Гуглить:** `golang array comparison` · `go comparable types`

**Должен знать**
Массивы одного типа сравниваются через `==` и `!=`: равны, если равны все элементы по порядку (при условии, что сами элементы можно сравнить через `==`). Массивы разной длины — разные типы, их сравнение не скомпилируется.
Поэтому массив годится как составной ключ, например `[2]int` для пары координат.

**Термины**
- **сравнение массивов** — `==` поэлементно, только для одного типа

### GO-7.2 Слайс

#### GO-7.2.1 Слайс
**Вопросы**
- [ ] Что такое слайс и чем он отличается от массива? · `go slice vs array`
- [ ] Почему у слайса тип `[]int` без длины? · `go slice type no length`
- [ ] Почему слайс называют «окном в массив»? · `go slice view of array`
- [ ] Чем слайс похож на `list` в Python и чем отличается (один тип элементов, общий массив)? · `python list vs go slice`
- [ ] Почему слайсы используют в Go почти везде, где в Python был бы список? · `go slices everywhere`

**Гуглить:** `go tour slices` · `go blog slices intro` · `golang slice explained`

**Должен знать**
Слайс — «окно» в массив: он не хранит элементы сам, а смотрит на кусок какого-то массива. Длина в тип не входит — `[]int` описывает окно любой длины, поэтому слайсы можно передавать в функции и растить.
Мост из Python: в повседневном коде слайс заменяет `list`. Но у него один тип элементов и, главное, общий массив: несколько слайсов могут смотреть в одни и те же данные. Отсюда почти все ловушки.

**Термины**
- **слайс** *(новое)* — окно в массив переменной длины: `[]T`
- **базовый массив** — массив, на который смотрит слайс

#### GO-7.2.2 Заголовок слайса: указатель, длина, ёмкость
**Вопросы**
- [ ] Из каких трёх полей состоит заголовок слайса и сколько он весит? · `go slice header ptr len cap`
- [ ] Что такое длина и ёмкость и как их узнать (`len`, `cap`)? · `go len vs cap`
- [ ] Почему ёмкость всегда не меньше длины? · `slice cap >= len`
- [ ] Почему при копировании слайса копируется только заголовок, а элементы — нет? · `copying slice copies header`
- [ ] Нарисуй заголовок слайса и его массив для `s := []int{1, 2, 3}`. · `go slice internals diagram`

**Гуглить:** `go slice internals` · `go blog slices` · `reflect.SliceHeader`

**Должен знать**
Слайс — это маленькая запись из трёх полей, заголовок: указатель на первый видимый элемент массива, длина (сколько элементов видно) и ёмкость (сколько элементов есть в массиве от начала окна до конца массива). На 64-битной системе заголовок весит 24 байта, сколько бы ни было элементов.
Присваивание слайса копирует только заголовок: две переменные смотрят в один массив. Это ключ ко всем следующим урокам.

**Термины**
- **заголовок слайса** — указатель на массив, длина и ёмкость
- **длина** — `len(s)`, сколько элементов видно через слайс
- **ёмкость** *(новое)* — `cap(s)`, сколько элементов доступно до конца массива

#### GO-7.2.3 Литерал слайса и функция make
**Вопросы**
- [ ] Как создать слайс литералом `[]int{1, 2, 3}`? Чем запись отличается от массива? · `go slice literal`
- [ ] Что делает `make([]int, 3)` и чему равны длина и ёмкость? · `golang make slice`
- [ ] Чем `[]int{}` отличается от `make([]int, 3)` и от `make([]int, 0, 3)`? · `make slice len cap difference`
- [ ] Какие значения у элементов после `make`? · `make slice zero values`
- [ ] Когда удобнее литерал, а когда `make`? · `slice literal vs make`

**Гуглить:** `golang make function` · `go slice literal vs make`

**Должен знать**
Литерал `[]int{1, 2, 3}` создаёт массив и слайс на него сразу (без числа в скобках — иначе получится массив). `make([]int, n)` создаёт слайс длины `n` с нулевыми значениями, `make([]int, n, c)` — длины `n` и ёмкости `c`.
`[]int{}` — пустой слайс: длина 0, ёмкость 0. `make([]int, 0, 3)` — тоже длина 0, но место под три элемента уже выделено.

**Термины**
- **make** *(новое)* — функция языка, создающая слайс заданной длины и ёмкости
- **литерал слайса** — `[]T{…}`

#### GO-7.2.4 Нулевое значение слайса
**Вопросы**
- [ ] Какое нулевое значение у слайса? · `go nil slice zero value`
- [ ] Чему равны `len` и `cap` у nil-слайса? · `nil slice len cap 0`
- [ ] Можно ли пройти nil-слайс циклом и добавить к нему элемент? · `range over nil slice append nil slice`
- [ ] Что будет при обращении `s[0]` к nil-слайсу? · `nil slice index panic`
- [ ] Почему `var s []int` — нормальный способ начать накапливать элементы? · `go var s []int append`

**Гуглить:** `golang nil slice` · `go zero value slice`

**Должен знать**
Нулевое значение слайса — nil: заголовок с пустым указателем, длиной 0 и ёмкостью 0. С ним можно работать почти как с пустым: `len` даёт 0, цикл ничего не делает, добавление элемента работает. Паника будет только при обращении к несуществующему элементу — как и у любого пустого слайса.
Поэтому `var s []int` и дальнейшее добавление — обычный способ собирать результат.

**Термины**
- **nil-слайс** — слайс с нулевым значением: без массива, длина и ёмкость 0

#### GO-7.2.5 Нарезка s[a:b]
**Вопросы**
- [ ] Что значит `s[2:5]`: какие элементы попадут и какая будет длина? · `go slicing s[a:b]`
- [ ] Что означают `s[:3]`, `s[2:]`, `s[:]`? · `go slice expressions omitted index`
- [ ] Можно ли нарезать массив и что получится? · `go slice an array`
- [ ] Чем нарезка в Go отличается от среза в Python (нет шага и отрицательных номеров, нет копии)? · `python slicing creates copy vs go`
- [ ] Что будет при `s[3:2]` или `s[0:100]`? · `go slice bounds out of range`

**Гуглить:** `golang slicing` · `go slice expression` · `python slice copy`

**Должен знать**
`s[a:b]` — новый слайс-окно с элементами от `a` включительно до `b` не включительно; длина `b-a`. Пропущенное начало — 0, пропущенный конец — длина. Нарезать можно и массив, и слайс.
Мост из Python: там срез создаёт копию. В Go нарезка ничего не копирует — новое окно смотрит в тот же массив. Шага и отрицательных номеров нет, выход за пределы — паника.

**Термины**
- **нарезка** *(новое)* — `s[a:b]`, новый слайс на часть того же массива

#### GO-7.2.6 Общий массив у слайса и его нарезки
**Вопросы**
- [ ] `s2 := s1[1:3]`, затем `s2[0] = 99`. Что будет в `s1` и почему? · `go modify sub slice affects original`
- [ ] Нарисуй оба заголовка и общий массив для этого примера. · `go slice shared backing array diagram`
- [ ] Как получить независимую копию части слайса? · `go copy slice independent`
- [ ] Почему это поведение не баг, а следствие устройства слайса? · `go slices share memory`

**Гуглить:** `go slice shared underlying array` · `go slices gotcha`

**Должен знать**
Нарезка и исходный слайс смотрят в один массив, поэтому изменение элемента через одно окно видно через другое: `s2[0] = 99` меняет `s1[1]`. Заголовки разные — у них свои начало и длина, — а данные общие.
Нужна независимая копия — её создают явно, отдельным массивом.

**Термины**
- **общий массив** — несколько слайсов смотрят в одни и те же элементы

#### GO-7.2.7 Ёмкость нарезки
**Вопросы**
- [ ] Чему равны `len` и `cap` у нарезки `s[2:4]`, если у `s` длина 10 и ёмкость 10? · `go cap of sub slice`
- [ ] Почему ёмкость нарезки считается до конца массива, а не до конца исходного слайса? · `slice capacity to end of array`
- [ ] Можно ли нарезкой «расширить» слайс обратно до ёмкости: `t := s[:2]; t = t[:5]`? · `go reslice up to capacity`
- [ ] Почему нельзя нарезкой заглянуть левее начала окна? · `go slice cannot go backwards`

**Гуглить:** `golang slice len cap reslice` · `go slice capacity explained`

**Должен знать**
Ёмкость нарезки `s[a:b]` — `cap(s) - a`: от начала нового окна до конца массива. Для `s[2:4]` при `cap(s) == 10` длина 2, а ёмкость 8.
Поэтому нарезку можно снова расширить вправо до её ёмкости и увидеть элементы, которые «за окном». Влево — нет: начало окна отрезает всё, что слева.

**Термины**
- **ёмкость нарезки** — от начала окна до конца массива: `cap(s) - a`

### GO-7.3 append

#### GO-7.3.1 Функция append
**Вопросы**
- [ ] Что делает `append` и что возвращает? · `golang append`
- [ ] Как добавить несколько элементов сразу? · `go append multiple elements`
- [ ] Почему `append` — это функция, возвращающая новый слайс, а не действие «на месте», как `list.append` в Python? · `go append returns new slice why`
- [ ] Можно ли добавить элемент в nil-слайс? · `append to nil slice`

**Гуглить:** `go append builtin` · `go blog append`

**Должен знать**
`append(s, x, y)` добавляет элементы в конец и возвращает слайс-результат: `s = append(s, x)`. Результат может смотреть в тот же массив или в совсем новый — зависит от ёмкости. Поэтому результат всегда присваивают обратно.
С nil-слайсом `append` работает: он сам создаёт массив.

**Термины**
- **append** *(новое)* — функция языка: добавить элементы и вернуть новый заголовок

#### GO-7.3.2 append, когда ёмкости хватает
**Вопросы**
- [ ] Что делает `append`, когда ёмкости хватает? · `go append within capacity`
- [ ] Почему новый элемент записывается прямо в существующий массив? · `append same backing array`
- [ ] Что тогда происходит с длиной у результата и у исходной переменной? · `append len of original slice unchanged`
- [ ] Нарисуй `s := make([]int, 2, 4); t := append(s, 7)`: какие заголовки и какой массив? · `append shared array example`

**Гуглить:** `go append capacity not exceeded` · `append behavior same array`

**Должен знать**
Если `len < cap`, `append` кладёт элемент в следующую свободную ячейку того же массива и возвращает заголовок с длиной на 1 больше. Исходная переменная по-прежнему имеет старую длину и новый элемент «не видит», хотя он уже лежит в общем массиве.
Это быстро — ничего не копируется, — но после `t := append(s, 7)` слайсы `s` и `t` делят массив, и дальнейшие записи через один видны через другой.

**Термины**
- **запись на месте** — `append` использует свободное место в том же массиве

#### GO-7.3.3 append, когда ёмкости не хватает
**Вопросы**
- [ ] Что делает `append`, когда ёмкости не хватает? · `go append exceeds capacity`
- [ ] Что происходит со старым массивом после переезда? · `append new backing array old array`
- [ ] Почему после переезда изменения нового слайса не видны через старый? · `append reallocation no longer shared`
- [ ] Почему переезд — дорогая операция? · `slice reallocation cost`

**Гуглить:** `go append reallocation` · `append new array copy`

**Должен знать**
Если `len == cap`, места нет: `append` выделяет новый массив побольше, копирует туда старые элементы, добавляет новые и возвращает заголовок, смотрящий в новый массив. Старый массив остаётся как был, и слайсы, которые на него смотрят, с новым больше не связаны.
Снаружи не видно, какой из двух случаев произошёл, — отсюда сюрпризы. Переезд стоит копирования всех элементов, но бывает редко, поэтому в среднем `append` быстрый.

**Термины**
- **переезд** — `append` выделяет новый массив и копирует в него элементы

#### GO-7.3.4 Правило роста ёмкости
**Вопросы**
- [ ] Как примерно растёт ёмкость при `append` и что поменялось в Go 1.18? · `go 1.18 slice growth formula`
- [ ] Почему ёмкость растёт в разы, а не на 1? Что было бы при росте на 1? · `amortized append doubling`
- [ ] Почему маленькие слайсы растут вдвое, а большие — медленнее? · `go slice growth large slices 1.25`
- [ ] Почему реальная ёмкость иногда чуть больше расчётной? · `go append capacity rounding size class`
- [ ] Напечатай `len` и `cap` в цикле из 2000 `append` и посмотри на скачки. · `go print cap growth`

**Гуглить:** `go slice growth strategy` · `go 1.18 append growth change` · `amortized analysis dynamic array`

**Должен знать**
При переезде ёмкость растёт в разы: маленькие слайсы примерно удваиваются, а с какого-то размера рост плавно замедляется примерно до 1,25 раза — чтобы не тратить слишком много памяти на огромных слайсах. Раньше граница была резкой (1024 элемента), с Go 1.18 переход плавный и начинается около 256. Потом размер округляется вверх под удобные куски памяти, поэтому ёмкость бывает чуть больше расчётной.

**Термины**
- **рост ёмкости** — во сколько раз увеличивается массив при переезде
- **амортизированная стоимость** — средняя цена операции за много вызовов

#### GO-7.3.5 Результат append и исходная переменная
**Вопросы**
- [ ] Почему результат `append` нужно присваивать обратно в переменную? · `go append must assign result`
- [ ] Что будет после `append(s, 1)` без присваивания? · `go append result not used`
- [ ] Почему `t := append(s, 1)` вместо `s = append(s, 1)` — источник багов? · `append assign different variable gotcha`
- [ ] Что подскажет компилятор, если результат `append` не использовать? · `append evaluated but not used`

**Гуглить:** `go append result not used` · `golang always assign append`

**Должен знать**
`append` не может изменить заголовок в твоей переменной — он возвращает новый. Без присваивания длина `s` не изменится, а при переезде новый массив будет просто потерян; компилятор поэтому не даст вызвать `append` без использования результата.
Правило: `s = append(s, …)`. Присваивание в другую переменную (`t := append(s, …)`) оставляет две переменные, которые то делят массив, то нет — вот откуда задачи «что выведет код».

**Термины**
- **присваивание результата `append`** — `s = append(s, x)`, единственная надёжная форма

#### GO-7.3.7 Заранее выделенная ёмкость: make с тремя аргументами
**Вопросы**
- [ ] Зачем заранее выделять ёмкость через `make`, если знаешь размер? · `go preallocate slice capacity`
- [ ] Чем `make([]int, 0, n)` + `append` отличается от `make([]int, n)` + присваивания по номеру? · `make len vs cap preallocation`
- [ ] Какую ошибку делают с `make([]int, n)` и последующим `append`? · `make with length then append zeros bug`

**Гуглить:** `golang preallocate slice` · `make slice capacity performance`

**Должен знать**
Если размер известен заранее, `make([]T, 0, n)` выделяет массив один раз: дальнейшие `append` до `n` элементов не переезжают и ничего не копируют. Это заметно быстрее и экономит работу сборщика мусора.
Частая ошибка: `make([]int, n)` (длина уже `n`, элементы — нули) и затем `append` — новые элементы окажутся после `n` нулей. Либо длина `n` и запись `s[i] = …`, либо длина 0, ёмкость `n` и `append`.

- **предвыделение** — заранее задать ёмкость, чтобы не было переездов

### GO-7.4 Слайс в функции

#### GO-7.4.1 Передача слайса в функцию
**Вопросы**
- [ ] Что копируется при передаче слайса в функцию, а что остаётся общим? · `go pass slice to function header copy`
- [ ] Сколько стоит передать в функцию слайс из миллиона элементов? · `passing slice cost`
- [ ] Почему говорят «слайс передаётся по значению», и при этом функция может изменить элементы? · `go slices passed by value but`
- [ ] Чем это отличается от передачи массива? · `go array vs slice parameter`

**Гуглить:** `golang slice function argument` · `go slices passed by value`

**Должен знать**
Слайс, как и всё в Go, передаётся по значению — но копируется только заголовок: 24 байта. Указатель в копии ведёт в тот же массив. Поэтому передать огромный слайс дёшево, а функция видит те же элементы, что и вызывающий.
Длина и ёмкость в копии заголовка — свои: если функция их меняет, вызывающий этого не видит.

**Термины**
- **копия заголовка** — при передаче слайса копируются указатель, длина и ёмкость

#### GO-7.4.2 Изменение элементов внутри функции
**Вопросы**
- [ ] Функция меняет элемент слайса. Увидит ли это вызывающий? · `go function modify slice element`
- [ ] Почему это работает, хотя функция получила копию? · `slice header copy same array`
- [ ] Как написать функцию, которая заведомо не трогает данные вызывающего? · `go copy slice before modify`
- [ ] Почему в документации функций пишут, меняют ли они переданный слайс? · `go document mutation slice`

**Гуглить:** `go modify slice in function` · `golang slice mutation`

**Должен знать**
Да: `s[i] = x` внутри функции пишет в общий массив, и вызывающий это увидит. Копия заголовка указывает туда же, куда оригинал.
Если функция не должна менять входные данные, она работает с копией. Хороший тон — явно писать в комментарии, изменяет ли функция переданный слайс.

**Термины**
- **изменение через копию заголовка** — запись в элемент видна всем, кто смотрит в тот же массив

#### GO-7.4.3 append внутри функции
**Вопросы**
- [ ] Функция делает `append` к слайсу. Увидит ли вызывающий новый элемент? От чего это зависит? · `go append inside function caller`

**Должен знать**
`append` внутри функции меняет только её копию заголовка, поэтому длина у вызывающего прежняя — нового элемента он «не видит». ### GO-7.5 Приёмы работы со слайсами

#### GO-7.5.1 Функция copy
**Вопросы**
- [ ] Что делает `copy` и сколько элементов он скопирует? · `golang copy function`
- [ ] Что вернёт `copy(dst, src)`, если `dst` короче `src`? · `copy min len dst src`
- [ ] Почему `copy` в пустой (nil) слайс ничего не копирует? · `copy into nil slice copies nothing`
- [ ] Как сделать полную независимую копию слайса двумя способами? · `go clone slice make copy slices.Clone`
- [ ] Можно ли копировать перекрывающиеся части одного слайса? · `go copy overlapping slices`

**Гуглить:** `golang copy slice` · `go clone slice`

**Должен знать**
`copy(dst, src)` копирует элементы из `src` в `dst` и возвращает их число — минимум из двух длин. Копирует он в существующие элементы `dst`, поэтому `dst` нужно создать заранее нужной длины: `dst := make([]int, len(src)); copy(dst, src)`. В nil-слайс не скопируется ничего.
Перекрывающиеся куски одного массива `copy` копирует корректно. Короткий способ полной копии — `slices.Clone(s)` или `append([]int(nil), s...)`.

**Термины**
- **copy** *(новое)* — функция языка: скопировать элементы из одного слайса в другой

#### GO-7.5.2 Трёхиндексная нарезка s[a:b:c]
**Вопросы**
- [ ] Зачем нужна трёхиндексная нарезка `s[a:b:c]`? · `go full slice expression`
- [ ] Чему равны длина и ёмкость у `s[1:3:4]`? · `full slice expression len cap`
- [ ] Как она защищает исходный слайс от затирания через `append`? · `three index slice prevent append overwrite`
- [ ] Почему третий номер не может быть больше ёмкости исходного? · `slice bounds out of range max`

**Гуглить:** `golang three index slice` · `go full slice expression append`

**Должен знать**
`s[a:b:c]` — нарезка, у которой длина `b-a`, а ёмкость ограничена: `c-a`. Если сделать `t := s[:2:2]`, у `t` нет свободного места, и любой `append(t, …)` переедет в новый массив, не тронув `s`.
Это способ отдать кому-то часть слайса, не рискуя, что он перезапишет остальное.

**Термины**
- **трёхиндексная нарезка** — `s[a:b:c]`, нарезка с ограниченной ёмкостью

#### GO-7.5.3 nil-слайс против пустого слайса
**Вопросы**
- [ ] Чем nil-слайс отличается от пустого? Что можно делать с nil-слайсом? · `go nil slice vs empty slice`
- [ ] Что вернёт `s == nil` для `var s []int` и для `s := []int{}`? · `nil slice comparison`

#### GO-7.5.4 for range по слайсу

#### GO-7.5.5 Переменная range и элемент слайса
**Вопросы**
- [ ] Почему изменение переменной цикла `range` не меняет элемент слайса? Как изменить элемент? · `go range value copy modify element`
- [ ] Что выведет `for _, v := range s { v *= 2 }; fmt.Println(s)`? · `range value is copy`
- [ ] Почему брать адрес `&v` в цикле не даёт адрес элемента? · `go range variable address not element`
- [ ] Как изменить элементы правильно через номер `s[i]`? · `go modify slice in range by index`
- [ ] Почему копия особенно дорога, когда элементы большие? · `range copy large struct performance`

**Гуглить:** `golang range copy value` · `go modify slice elements in loop`

**Должен знать**
`v` в `for _, v := range s` — копия элемента, а не сам элемент. Изменение `v` ничего не меняет в слайсе, и `&v` — адрес переменной цикла, а не элемента. Пример выведет исходный слайс.

**Вопросы**
- [ ] Как удалить элемент из середины слайса? · `go remove element from slice`

Выход — скопировать нужный кусок в новый маленький слайс (`slices.Clone`), тогда большой массив освободится. По той же причине при удалении из слайса указателей «лишние» элементы в хвосте обнуляют, чтобы они не удерживали данные.

**Термины**
- **удержание памяти** — маленькая нарезка не даёт освободить большой массив

#### GO-7.5.9 Вариадические функции и запись s...
**Вопросы**
- [ ] Что такое вариадическая функция и что значит `f(s...)`? · `golang variadic functions`
- [ ] Каким типом становится параметр `nums ...int` внутри функции? · `variadic parameter is slice`
- [ ] Почему `fmt.Println` принимает сколько угодно аргументов? · `fmt.Println variadic`
- [ ] Копируется ли слайс при вызове `f(s...)` или функция видит тот же массив? · `go variadic slice shared array`
- [ ] Чем это похоже на `*args` в Python? · `python *args vs go variadic`
- [ ] Почему вариадический параметр должен быть последним? · `variadic parameter must be last`

**Гуглить:** `golang variadic function` · `go spread slice ...` · `python *args`

**Должен знать**
`func sum(nums ...int) int` принимает сколько угодно `int`; внутри `nums` — обычный `[]int`. Вызвать можно `sum(1, 2, 3)` или передать готовый слайс записью `sum(s...)` — тогда новый слайс не создаётся, и функция видит тот же массив.
Вариадический параметр может быть только последним. Мост из Python: это аналог `*args`, только все аргументы одного типа.

**Термины**
- **вариадическая функция** *(новое)* — функция с переменным числом аргументов: `...T`
- **`s...`** — передать элементы слайса как отдельные аргументы
